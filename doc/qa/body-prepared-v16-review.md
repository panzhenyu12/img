# 身体蒙版与同进程分层缓存性能

2026-10-14。本轮先冻结旧 native CLI，再只优化身体路径的重复蒙版解析与分层缓存。**输出没有改变，不把效率改善记作美学分数提升。**

`body.rs::rasterize_mask` 的 base mask 先编译为 `PreparedMask`，raster alpha 一次解码、polygon 一次读取和包围盒剔除；原 brush stamp 顺序、局部 footprint、反选和坐标浮点运算顺序保留。已有浏览器单项 F/B 缓存扩展到 native thread，严格比较源图字节和完整 alpha；只保留一项，内存上限16MiB。新图片、新alpha或透明度变化不能重用错误的分层。

五张真实照片、十五个部位，用冻结v14 graph与蒙版，逐项回放 `-60/-30/+30/+60`，共60项。每项都验证固定二进制哈希；候选与旧结果**逐字节一致**，冻结区与支持域外变化均0，收缩时原已知背景变化0，alpha变化0。参数/图像哈希、每项耗时和原图/基线/候选裁切见 [完整回放](body-prepared-v16/report.json)。这些是工程合同；宽袖/遮挡部位和窄带接缝质量仍保留旧评分。

四个代表graph在同一native进程各做首次1次、热运行5次，前后顺序交替，输出同样逐字节一致。记录包含graph JSON解析、验证、编辑和合成，不含检测、PNG或进程启动；现场有并发编译/开发负载，不能作为正式性能验收：

本组热运行耗时为旧版19.1%–23.6%（约4.2–5.2倍），首次耗时也明显下降；完整原始样本见 [性能JSON](body-prepared-bench.json)。首次改善主要来自 `PreparedMask`。浏览器已有F/B缓存；本次新增native缓存不会额外给浏览器带来该项收益。Go当前若每次调用新CLI进程，只享受首次优化，不能把同进程205–265ms直接宣称成API端到端耗时。

新增native缓存失效回归将缓存结果与新鲜 F/B 估计比较，依次覆盖重复图片、改图、改alpha、返回原图、非opaque图、再返回opaque图。缓存只是复用相同计算，不能替代身体部位解析或窄缝背景重建。

浮点harmonic窄带补全另立候选，修改画质时必须重新看多图；没有实拍收益时不合入默认代码。
