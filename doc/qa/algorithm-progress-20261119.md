后续单独增加整张源与解剖轴旋转90°的反例测试并通过：修正轮廓随人物轴旋转，不依赖画布的横行，遮挡证据状态保持一致。没有因此重跑上述8项或重渲染已审核照片。fullbody-skirt 经额外独立审图确认，旧有普通收腰在 ±30 有轻度实际响应、裙褶和袖侧连续；它可支持该既有样片的功能有限可用，仍不算 V2 新增纠边的第二阳性。

腿部与上臂新增普通入口回放见 [逐项记录](body-limb-current-20261119.md)。当前推进顺序：冻结已验收的常用收腰规则，集中修仍被拒绝的眼高/眼睑轻闭合，验证眼角固定、虹膜及高光保形、睫毛无双影，避免继续在同一腰部样片调参。算法源准备仍存在每次滑杆重复计算的成本，性能优化须保持现有成片，不能以降低精度或取消形变替代。

眼部新源流程已不依赖 user/dark 的历史 source-states 或旧场：每眼仅准备一次，同一源层复用于零值及两档闭合。三张新源的身份、坐标适配、解码域差异和逐项视觉边界见 [新源轻闭眼验收](eye-closure-fresh-source-20261119.md)。当前仍是显式本地 native 场生成器与 Python 分层合成的算法实验，不是已分发的 Rust 公共功能。[FUNC-078](../func/FUNC-078-eye-source-material-correction.md) 已实现与光学 alpha 分开的人工源材料修正；已知层最终 RGB/位置与用户原图眼球修正均已有证据，人工结果不计作自动识别成功。

照片、模型和输出仅保留本地，不提交远端。所有可用性结论仅对应明确样本、参数和输入合同。


## 普通原图入口与人工轻闭合补充

[FUNC-079](../func/FUNC-079-native-eye-closure.md) 已提供普通 Rust `prepare_eye_closure`：原图＋478 点观测＋分类标注直接准备源层，后续复用到整数 `[-30,0]`，不再依赖 Python、预制数组或历史测试程序。未接 Web/Go/WASM，通用 `feature.adjust` 的眼高入口仍保留限制。

用户原图已有标签的轻闭合有限通过；makeup 首轮原标签未能保护虹膜高光，完整双眼验收失败。随后在原图上明确增加两个可见眼球标注，普通 Rust 第二轮 `−5/−15/−22/−30` 完整眼部、全脸及标注接界经独立审查通过；这是**可纠错的人工轻闭合能力**，不是自动算法达到 8 分。原细睫毛的 13 个颜色模型不确定像素继续报告，不用源 RGB 重建成功替代真实效果。

新增 15 项算法行为测试通过（含后续精确支持域优化），同解码同场 Python/Rust 最终 RGB 相同。31 档检查支持有限采样连续性，但不能覆盖未标区域的材料错误；原始失败和第二轮修正都保留，见[独立实图记录](eye-rust-material-route-20261119.md)。


眼部源残差已提前一次准备，支持外场求值减少覆盖读取；两原图五档成片/field哈希保持不变。同机顺序三次的 makeup −30 渲染中位数约310→282ms，源准备约293→333ms，仍非60fps。旧算法已有零速度早退，未通过降低积分步数或精度换速度。这里是新眼部算法的计算改进，不改写前述瘦脸5.7/6.1秒的既有结果。

## 瘦脸源背景复用

[FUNC-080](../func/FUNC-080-source-background-cache.md) 增加调用者持有的单项源缓存，精确比对背景重建与配对的完整输入，仅复用该纯源阶段。实际测得原调用约5.36秒中约2.90秒花在这一步。冻结胡茬样片的零值、±30、±60及三次重复输出共8次，与此前已审查RGBA全部相同；首次填充约5.27秒，+30热调用三次中位数约2.43秒，原接口三次中位数约5.40秒。四项定向测试与独立缓存边界审查通过。**这是保留效果的计算优化，仍未达到实时交互，也不增加算法美观评分。**
