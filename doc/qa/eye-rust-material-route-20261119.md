# 眼部人工材料修正：普通 Rust 路线独立审查

日期：2026-11-19。审查角色为独立全局算法 review；本文先冻结迁移目标与有限验收范围，后续追加实际 Rust 结果。未在此审查中重复运行模型或整套测试。

## 本轮应消除的具体不可用点

当前 Python 实验虽能从新原图准备源层，仍需一个既有 `cfg(test)` 场生成可执行文件，并通过磁盘 inverse 数组与 Python 合成协作。外部普通调用者无法仅凭源码库中的正常算法接口复现成片。另有正常虹膜被误判为眼睑、细睫毛被漏判的问题，用户无法在算法入口纠正材料身份。

本轮交付应是一个普通 Rust 算法入口：原图、绑定同一原图的观测、离散源材料标注、轻闭合参数，直接生成结果和诊断。源准备只做一次，同一准备对象复用于多个强度。无需隐藏底色、光学 alpha、历史 `.npz`、冻结 inverse、测试可执行文件或编辑后图。几何曲线输入可以是中间层，但最终仍须补齐原始 478 点观测到源曲线的常规路径。

这解决调用与人工纠错缺口，不意味着语言迁移本身改善画质。Web、MCP 和服务接入不属于本轮验收。

## 允许的输入与源准备

| 环节 | 必须保留的约束 | 不应强加的额外门槛 |
|---|---|---|
| 原图与观测 | 尺寸、方向、脸索引、坐标约定一致；文件 CLI 绑定原图 SHA，库内准备对象拥有或绑定其原始像素。多脸明确选择 | 不必把已验证的普通原图每次重新检测；绑定同源的观测可以复用 |
| 解码 | 准备与最终合成使用同一解码像素；跨 Pillow/Rust JPEG 差异应分开记录 | 不要求不同 JPEG 解码器逐字节相同，也不能拿解码差冒充算法差 |
| 几何 | 478 点生成眼角坐标系、顺序 PCHIP 先验及源 RGB 侧眼白局部修正；曲线不得交叉 | 几何曲线不是光学 alpha，不要求从单 RGB 证明真实三维眼形 |
| 坐标 | MediaPipe 的 normalized × dimensions 与 native 整数像素索引之间只转换一次；材料标签直接使用原图像素索引 | 不在场或合成端重复减 0.5；region 边界与几何点各自保留其约定 |
| 人工标签 | `ocularAnchors`、`movingLashSupport`、`unknown` 是互斥类别；禁止 opacity、alpha raster 或结果差分输入。拒绝跨眼冲突、空形状、错图/错尺寸及无声裁掉的标注 | 不要求用户手绘真实半透明 alpha 或隐藏眼球底色 |
| 基线源估计 | V1 只读取原图与源几何；源采样支撑扩展先于人工 unknown 应用；参数不因目标强度而改变 | 不把被拒绝的 V5/V7 自动 track 权限夹带进人工接口 |
| 明确移动材料 | 供体来自明确可见眼球；源三色模型推断底色与曝光比例，保留有界源重建及诊断 | 人工已确认身份时，颜色拟合残差较大可报告 `modelUncertain`，不因任意一倍噪声阈值重新否认身份 |

人工身份不消除颜色估计的不确定性。`estimated`、`modelUncertain`、`unknown` 必须区分：前两者可以接受实际视觉验收；无供体、域外或数值非法形成的 unknown 仍阻止依赖它的编辑。单张照片无法唯一恢复的 alpha/隐藏底色不是本轮死门槛，也不能写成已恢复真值。

## 输运与合成

当前有限方案保持眼球底色在源位置，移动眼睑/睫毛残量：源图满足 `C = R + E × B`，目标为 `sample(R,q) + sample(E,q) × B`。这是一项明确建模假设，不能推广到大角度转头、视线改变或完整睁眼。

必须核对以下实际行为：

- 普通场生成不读取测试环境变量、历史 inverse 或测试函数；所有目标场生成发生在源准备之后。
- 逆采样使用双线性供体；unknown 审查覆盖移动目的像素和所有实际贡献的供体，不能只检查中心点。
- 目标仍需要眼球底色时，其位置应有源观察或明确标为估计的合法支撑；完全无支撑的位置拒绝，不裁剪 RGB 或悄悄冻结整个眼睛。
- 细睫毛移动能露出旧位置，因而不能强制逐像素 `E_target <= E_source`；这些微小露出允许明确估计的底色。
- 零请求保持原图，选定支持之外和显式静止部分保持原图。微小请求不能借 epsilon 全部吞掉。
- 不将眼球连同眼睑整体竖向压扁；验收要看眼裂高度、虹膜、高光和睫毛，而非仅像素变化数。
- 普通输出量化允许正常四舍五入；不允许用输出 RGB clip 掩盖非法层或强度造成的失败。

原实验眼角存在约 0.006–0.018 px 的小残差，不新增精确 0 的审美门槛。原 `−30` 请求实际约为 6.8% 眼裂高度变化，验收不得误称减少 30%。

## 冻结的有限验收清单

| 检查 | 本轮可接受证据 | 不应被替代成什么 |
|---|---|---|
| 普通调用 | 源图 + 原始观测 + 分类标注，经普通库/CLI 冷准备得到零值和两档轻闭合，临时输出目录无历史数组输入 | 只公开 `compose(alpha,B,inverse)` 或从 Python 导出 prepared 缓存 |
| 源复用 | 同一 prepared 对象依次及换序渲染 0/−15/−30，准备状态不变；图像和标签绑定有效 | 每个强度重估源层、按输出残差更改标注 |
| 材料行为 | 保留两个 known-layer 的原 RGB/质心质量门槛；估计器只获得原图、类别和源几何 | 将 oracle alpha/B 输入算法，或把自动 V5/V7 失败改成通过 |
| 用户原图 | 冻结原 polygon；两眼全眼、虹膜及高光、−15/−30 接界、−30 全脸独立复核 | 仅恢复两个 RGB 探针；把左眼剩余误差写成完全恢复 |
| Makeup 原图 | 冻结 26 像素 moving、38 像素 donor 标注；两眼完整及标注睫根/线身接界复核 | 已有 V5+manual 图自动为新 V1+manual 背书；只检查被标注的一只眼 |
| 失败输入 | 已确认的错误绑定、冲突/域外材料、缺供体和 unknown 依赖明确失败；正向睁眼/超范围请求不冒充支持 | 返回原图同时报告成功，或默默缩小强度 |
| 数值迁移 | Rust 对应同解码源的 Python V1+manual 基线；差异需归因到几何/源层/场/量化，再看最终图 | 以严格逐位相同替代视觉验收，或因几张差异小就宣布普遍可用 |

普通请求至少覆盖已审过的轻闭合档。连续参数支持若尚未验证，应明确范围；不必一开始承诺完整 −100..100 或所有眼高/眼睑组合。

迁移实图通过后，支持整数 `[-30,0]` 是合理的下一步，不应因旧实验只取三档就永久限制成三挡工具。固定源层下，速度场幅度与双线性分层合成均随参数连续；剩余风险是积分步数取整的小数值跳变、反采样足迹在中间档碰到 unknown/支撑边缘，以及临近零值的输出量化。建议同一 prepared 对象扫该区间的 31 个整数做几何/unknown/源状态检查，并新增 `−5/−22` 完整眼部与材料接界审图。端点通过不能自动代表中间档；这些检查也不要求 8bit 图像每一档都改变每个像素。范围扩展另记实际结果，不借三档历史验收。

## 必须保留的局限

1. 用户图已审手工结果使用 V1，makeup 已审手工结果使用 V5。迁移采用 V1 是明确取舍，新 makeup 未标注区域须重新检查；已有 V5 实拍通过不能直接继承。
2. 本轮是人工材料修正路径。自动识别虹膜/细睫毛仍有已知反例；不得据此打开原公共 `eyeHeight`/`eyelid` 的全部参数。
3. 没有观察到的完整眼球结构、睁眼露出、侧脸/眼镜/遮挡与强闭合不在本轮有限证明范围内。
4. 暂不宣称实时性能。源准备与每次渲染应分别测量；无需为了一个源准备迁移重做 Web/Go/WASM 全系统构建。
5. 照片、标签与观测数据、模型和输出留在本地忽略目录，代码文档可提交。

## 第一阶段源码 review

此阶段先审路线与 Python 参考合同，当时普通 Rust 实现仍在推进，尚无成片验收结论。下文依实际新增证据与具体失败追加，不将单图改善或迁移完成提升为整套功能可用。

首轮只读源码审查已检查 `eye_source.rs`、`eye_material.rs`、`eye_closure_field.rs`。源层准备、明确材料三色估计、unknown 依赖检查及普通场提取符合上述分工；`PreparedEyeEdit` 拥有原图和冻结观测，`render(amount)` 不再接受另一张原图。原 generic 眼高操作仍保持其原准入边界。

发现并反馈的一个具体缺口已在源码修正：几何中间 API 原先只检查 width 有限且大于 2，随后按 width × 16 循环，可能被异常巨大或越图曲线拖住；PCHIP 非有限结果也可绕过单纯的交叉比较。当前增加原图对角线范围、曲线与眼角线位于准备 crop、求值有限检查。源 proposal 的 3 px 外侧 nearest 取样是原 V1 规则，未因此增加一圈不必要的拒绝区。这是源码复核，待实现方的定向回归证据，不另跑重复测试。

## 普通 Rust 首轮实际结果

本地结果为 `test/results/eye-closing-source-20261119/native-v1/{user,makeup}/`。两个源均从原文件、绑定的原始 478 点观测和已有冻结类别标注冷准备，随后复用同一对象得到 `0/−15/−30`。没有 `.npz` 源层输入、历史场、测试可执行文件或 Python 运行依赖。CLI 的 `--save-fields` 仅输出诊断，不读取外部场。

`eye_localize.rs` 已独立阅读：入口先校验完整不透明 RGBA 和所需源关键点范围，包括右眼 398 与虹膜环；physical crop 不减半像素，仅 origin/采样转换；侧眼白证据、有限带边缘搜索、先验位移正则及眼角固定与 Python 参考一致。QP 用已有 Clarabel 求解同一有界目标，没有将眼睑本身平滑成直线。实现方报告 14 项定向测试通过（材料 4、定位 3、场 4、公共源入口 3）；review 未重复运行。

同解码对照位于每个源的 `python-reference/`：Python 重新从 native `source.png` 和原始观测准备 V1，再使用同样冻结标注与 native 场合成。两源三档最终 RGB 均逐字节一致，源曲线最大差小于 `4e-11 px`。这证明迁移等效，不证明原 V1 分类正确。

独立检查两源原图、`−30` 全脸、四只完整眼睛在 `−15/−30` 的对照，以及 makeup 高光的 12 倍原像素放大：

| 源 | 结论 | 具体依据 |
|---|---|---|
| user，既有 61/68 像素 ocular polygon | 该人工修正、两档轻闭合有限通过 | 轻闭合可见；完整虹膜、眼睑接界没有新增硬边/双线/暗环。高光较未修正 V1 明显改善，左眼既有小残差仍保留，不能称完全恢复 |
| makeup，既有右眼 26 moving + 38 ocular donor 像素 | 完整双眼验收不通过 | 手工标记的细睫毛支路未见新双影，但两眼未标高光有压平；右眼可明确确认仍可见反射被错误削弱。不能继承旧 V5+manual 的实拍通过 |

最明确的反例是 makeup 右眼原图索引 `(695,370)`：源 RGB `[235,240,255]`，`−30` 输出 `[81,92,121]`，最大通道差 154。该点在源眼裂内约 3.274 px，逆采样位置 `[694.8678,368.8933]` 仍在眼裂内约 2.160 px，四个实际双线性供体的内侧深度约 1.186–2.278 px。结合完整原图与放大图，不能将这处反射损失解释为已经被新眼睑遮住。左眼顶部有些点确实接近或越过新眼睑位置，故不把所有高光变化都一概判成错误。

makeup 的 26 个 moving 像素均有合法估计，13 个报告 `modelUncertain`，0 个结构 unknown；这并不能取消未标区域的上述缺陷。局部补好了材料与全眼可用是不同结论。

本机并发运行的源准备约 user 121 ms、makeup 196 ms；非零渲染约 user 89–90 ms、makeup 229–301 ms。来自该次普通入口报告，非独占性能基准，也不支持 60fps 声明。

## 发现首轮缺陷后的具体推进决策

推荐继续走明确的人工材料修正路径：在原图上确认两眼仍可见眼球区域，保留原睫毛 moving 标注，用普通 Rust 重新 prepare 并审整眼接界。这应明确记为**人工第二轮修正**，不能说冻结标签盲测或自动算法改善。源图人工编辑本就允许修改类别，不必为了维持一次性盲测姿态让手动工具永久失败。

本轮不建议为语言迁移再完整移植已知反例仍失败的 V5 检测堆叠，也不建议临时另起一个新自动模型而搁置已能调用的手工功能。先形成范围清楚、用户能够纠错的轻闭合算法；后续测量实际人工标注成本，再决定改进自动建议层。普通无标 V1 路径仍不应被宣传为自动可用。

以上是首轮失败后的决策，随后实际结果如下。

## 人工第二轮修正与中间档：有限通过

第二轮分类文件为本地 `native-v1/material-correction-r2/materials.json`，SHA-256 为 `8a8f6b181f85ab4e6836258a1b5c49b58b29e5b9747579e682de2e9684966fee`。在源图网格上增加两处可见虹膜/眼球 polygon，保留原 26 moving 像素及 38 个眼白供体。左眼首个 polygon 的上缘 y=367 有六个像素越出原几何域，出图前被拒绝；标注明确改到 y=368 后重新冻结，没有修改源几何或放开域检查。被拒绝的 JSON 保留。这是人工迭代，不能记作原冻结标签自动通过。

结果目录 `native-v1/makeup-manual-r2/` 由同一普通 Rust prepare 对象生成 `0/−5/−15/−22/−30`。同解码 fresh Python V1 加相同新标签的五档对照，最终 RGB 均与 Rust 一致。

独立查看两眼四个非零档完整对照、`−30` 全脸、源标注，以及 10 倍完整虹膜/人工 polygon 接界：

- 先前反射压平明显改善；右眼 `(695,370)` 四个非零档均保持源 `[235,240,255]`。判断同时基于整个高光形状和虹膜，未只验这一个点。
- 没有发现新增 polygon 硬边、暗环、双睫线或眼睑断口；原已标细睫毛未出现新的明显残影。
- 左上反射与眼睑接近处随轻闭合发生局部变化，不能要求合理遮挡区域也完全静止；当前完整眼部仍自然。
- 全脸轻闭合成立，未观察到将整个虹膜竖向压扁或新拼补接界。

据此接受 **makeup 第二轮人工源材料纠正后的四档轻闭合有限可用**。保留首轮失败、自动未通过、13 个 `modelUncertain` 和非真实 alpha 的边界；不能宣布任意新图无标注即可使用。

整数范围的数值检查已读取 `user-sweep/sweep-audit.json` 与 `makeup-sweep/sweep-audit.json`：两者均准备一次、遍历 31 档。user 最小采样单元 Jacobian 约 0.92947，最大相邻档位移约 0.02120 px；makeup 约 0.93048 和 0.04131 px。相邻位移差的最大值分别约 0.0000863 px、0.0001526 px，没有由积分步数取整造成明显场跳变。makeup 数值 sweep 使用首轮标签，不能覆盖它的高光视觉失败；材料标注不改变运动场，第二轮另以五档成片支持材料效果。user 新增 `−5/−22` 完整眼部 sweep 图也已独立检查，未见新的接界或反射损伤。

本轮普通算法能力是：源图加观测和人工材料纠正、固定源层复用、范围明确的轻闭合。它消除了必须使用实验缓存和无法纠错的调用障碍；仍不是完整睁闭眼、所有照片自动识别或整套修图功能达到 8 分。
