# v19 脸型与上颈的分阶段诊断

2026-10-14。只读生产代码和冻结 v19 四档仪器数据；没有重新检测、运行求解器或修改生产。Root 已确认这些候选输出与当前 production 四档全 RGBA 一致。逐点数据见 [report.json](report.json)，输入和当时生产哈希见 [provenance.json](provenance.json)，复现脚本为 [diagnose.py](diagnose.py)。

结论：+100 的直尖下颌及夹窄上颈主要来自**目标与约束不具备部位语义**。附件可行性先把上脸的约 20px 请求归零，把收缩集中到耳饰以下；QP 将这个急变目标桥接成接近直线的下颌；RBF 准确实现该目标并将它传播到没有独立目标的上颈。分割边缘会造成碎点和硬边，但不能解释几十像素的整体形状变化。减小 strength 会缩小问题，并不修复目标设计。

## 哪个阶段改变了形状

`target_contour` 以眼线坐标里的整脸宽、高和中心作横向位移，faceWidth 在归一化高度 .34–.88 内基本等量内收，然后在 .88–1 退到零。没有识别颧弓、下颌角、下颌体、颏部圆弧；也没有沿实际外轮廓法线移动。+100 在此原照的最大请求约20.02px。原下颌标签终点被保留，两侧广泛等量内收，天然倾向改变下颌夹角。它也作用于内部 face/neck 语义交界，无法区别该交界与真实皮肤外缘。

这不是“QP 让所有上脸固定”：固定/归零已经出现在 QP 前。附件保护不能取消，但需要让目标生成器知道可用的曲线区间，避免先请求整个侧脸相同位移再机械裁掉上半段。

QP 的影响可量化：+100 相对附件可行目标，左/右最大侧向修正5.145/4.034px；-100为11.825/11.175px。+100左右各29点中的27个二阶约束，左侧贴住源曲率下限的数量从7增到13，右侧11增到13。这说明约束实际介入，不是无效模块。约束形式是侧曲线 `u(source-v)` 不增加反向或负曲率；当原局部曲率为正，其下限为0，允许将真实转折压到直线。它没有保持下颌角、曲率峰值位置或颏部半径的目的，不能作为“自然脸型”保证。

QP bending 项对 displacement 使用 `[1,-2,1]`、统一权重3。虽然沿 polygon 全周弧长均匀采128点，筛出侧曲线后 source-v 间距不均匀：左右最大/最小比2.398/2.651。约束按 v 间距算斜率，但 bending 惩罚没有间距和积分权重；换轮廓采样密度/脸姿态会改变其物理意义。此处证明不均匀性和约束接触，尚未做单独 QP 消融，不能将全部压平幅度归因于 bending 项。

最后的 RBF/SVF 在此照 +100 活跃控制点最终最大误差0.297px、RMS0.117px。真实曲线贴近紫色可行目标。局部纹理/非控制点仍可能变形，但目前证据不支持把尖下颌主要归因于积分不准或 inverse map 错误。

## 为什么上颈跟着夹窄

联合 alpha 解决了脸/颈材质断接，却没有给颈侧提供独立的源曲线、请求目标或形状约束。RBF 控制点仍仅沿 face polygon 和五官锚点布置，半径约脸宽*.31；上颈边缘处于其邻域，直接继承下脸速度。

冻结仪器记录的实际 landmark Frame 高352.486px。沿实际眼线坐标中轴，neck falloff 起点全图约y617.391，终点y709.035；这采用 instrument 的 anatomical frame，不能用另一条原polygon bbox 的理论代数替代。发生夹窄的y545–600处，neck_motion 本身尚未衰减。

同一量化物理alpha的中心连通行区间：+100在y495只缩3px；y525缩35px；y545从408..613变429..591，宽度缩43px（约21%）；y560缩40px；y600缩7px。-100对应y545扩大34px。该alpha由parser/RGB校正得到，并非人工真值，但几十像素的形状变化也可直接在实际Web RGB比较中看到，不能解释为一像素阈值或漏分碎点。

另查源外边缘内2px的分类，[edge-class-transition.json](edge-class-transition.json)：y535仍为face；y541–550向neck转换，但两侧不对称。y545左侧face=.0375、skin=.754、neck=0，右侧face=0、skin=.964、neck=.874；y550左neck=.5、右neck=.956；y580两侧neck约1。左侧存在分别阈值化后neck标签缺口，不能用一条横切线或单独neck>.8作为外部皮肤/颈部解剖边缘。

## v20可证伪的改进目标

先为颧弓、下颌角到下颌体、颏部及外部颈侧建立**分别参数化的源曲线**，保留个人的角点/切线/圆弧，不对它们套同一 y-profile。以 landmark 提供部位位置，parser/RGB 外缘提供可见边界；无法确定的内部标签交界不能作为外轮廓控制真值。

可行性先进入目标规划：耳/耳饰端点固定时，在该部位曲线的可编辑区间完成 C1 连接，保持下颌角位置和邻接切线，再优化请求位移及曲率变化。零 strength 必须为 source；不要用全域“凹曲率禁止”消除合法的颧颊/下颌转折。若采用曲线能量，应按真实弧长/非均匀间距离散，使重新采样不改变目标。

脸宽调整应对颈侧定义单独的 shape-preserving 目标或明确的允许位移，面颈内部继续共同运输以避免破洞。禁止简单硬钉整段上颈造成回到旧材质断接；也不能让自由 RBF 扩散决定颈形。v20至少同时报告真实外脸侧曲线、下颌角/颏部切线变化、颈侧宽度与局部应变，以及requested/feasible/actual逐阶段残差。

可验收的回归包括：相同实际内收幅度比较，原下颌转折仍有可辨曲率变化；同一曲线倍增/减半采样后目标差异接近浮点与插值误差；没有 neck 调整时颈侧宽度变化遵守明确预设范围；两侧及±30/±100分别测。上述是待验证的设计要求，不是本轮已证明8分的结果。

## 五官的独立诊断

geometry.rs 已有独立 feature bounds、部位中心/尺度以及专门鼻根/鼻尖/鼻翼语义，不是全脸统一拉伸。但所有 LocalWarp 仍用椭圆 `d=(u/rx)^2+(v/ry)^2` 与 `(1-d)^2` 衰减 affine/translation/rotation generator；多 warp 的 stationary velocity 相加。语义 polygon 只决定 frame/bounds，未定义整条眼缘、眉缘或唇缘的目标。

eyeTilt 只有中心是严格旋转 generator，整眼各点权重不同，眼缘与虹膜因此旋转不同角度；eyeSpacing 也在眼内衰减 translation，会改变眼形。V4b修正了旋转generator以及数值/零点/字节问题，不能从中心det≈1推广为整个眼域刚性。browPeak、lipPeak、lipCorner仍是局部圆/椭圆位移，与真实眉峰、唇峰弧线的曲率/切线不一一对应。

下一独立候选只研究 eyeTilt/eyeSpacing：以原语义眼polygon及完整运动轨迹形成平坦核心，使整个可见眼缘/虹膜具有同一刚性运动；核心外部作C1过渡。先证完整多边形边长、面积、角度及外部冻结约束，不改动鼻翼/嘴型算法，也不能套同一眼模板去处理它们。
