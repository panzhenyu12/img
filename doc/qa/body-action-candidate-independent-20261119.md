# Action-suit：独立源图与候选表达能力审查

本次结论：自动原路径仍不可用。SAM2 候选库确实提供了比 FASHN 单类衣物更多的左右袖信息，支持继续验证**事先约定的候选集合组合**，但这还不是已完成的自动部件识别，更不是图像修改效果通过。

## 先冻结源图事实

西装胸衣与两袖属于同一件**穿着中的衣物**，部件运动可以不同。右侧开襟衣摆不等于静止背景，也不是 side-fashion 样本中的独立悬挂外套。可见衣物外沿不等于被衣服遮住的解剖腰线；电脑下方不可见的人体轮廓没有真值。肩袖连接、遮挡后的材料、分数 alpha 和前后顺序均不能从这些矩形标签推出。

## 现有自动结果失败在哪里

body 实现 agent 的同源诊断报告：右侧预先冻结衣缘 ±4px 带 3168 像素在 ±30 下 RGB 和位移均为零；左侧短衣缘 914 像素 RGB 不变且 `partMask>0.5` 为零；内部最大位移为 11.49px。以上数值来自实现 agent，不冒充本审查者独立重跑。

本审查者独立读取本次保存的 FASHN posterior：三块西装躯干核心平均 `top` 概率分别为 0.9098、0.9036、0.9023；四块衣袖为 0.9075–0.9111；白衬衫为 0.9108。它识别出了上衣材料，却不区分同一衣物内的袖与胸衣。手分别为 `hands` 0.9184、0.9068；电脑被分为 `bag` 0.9111，不能把类名当作对象真实身份。

因此，现象不是“衣服整体没被检测到”，而是现有强制骨架归属及变形支持域丢掉了可见衣侧。白衬衫内部发生变化、没有出现裂缝，都不足以证明收腰成功。

## 完整候选库的独立检查

检查对象为 `test/results/body-material-candidates-20261119/action-suit/` 下全部 81 个候选（27 个源图自动查询，每个保留三个 multimask），五张总览与必要的原分辨率结果。没有按模型 score 排名，没有改提示或修 mask。

独立核心覆盖矩阵保存于 `/tmp/body-independent-20261119/action-suit/candidate-core-coverage.json`。以下 ID 仅说明“库中是否存在”，**不是自动算法的候选选择表**。

| 观察 | 支持的结论 | 仍未支持 |
|---|---|---|
| `r3c0-m1`、`r4c0-m1` 覆盖两块左袖核心 100%，三块躯干核心 0% | 存在左袖部件级信息 | 肩根缺失/碎裂，少量手部误入；不是完整可靠袖 mask |
| `r2c3-m2`、`r3c2-m1` 覆盖两块右袖核心 100%，三块躯干核心 0% | 存在右袖部件级信息 | 肩根界线及袖口光学分层尚未验证 |
| 多个完整人物候选覆盖三块躯干与四块衣袖核心 100%，电脑及背景核心 0% | 衣物总体支持没有完全缺失 | 人物候选还包括头/手/裤，不等于 torso |
| 较大衣物候选也能覆盖三个躯干核心与双袖核心 | 可用上衣类支持限制整体候选，再减去袖候选，形成躯干部支持的表示 | 自动联合分配是否选对、是否保住可见衣缘尚无结果 |
| 未发现单个干净候选同时包含两侧西装躯干且完整排除双袖 | 单 mask 直取 torso 不成立 | 不能据此否定从一开始声明的集合组合方案 |

左右袖候选和完整衣物支持提供了组合所需的信息。这只通过**稀疏确定核心的表达能力检查**；没有通过所有边界、完整部件召回或最终编辑验收。原图不能确定的肩袖接缝仍应保留不确定性。将孔洞、碎片全部交给 matting，也不能代替缺失的材料身份判定。

下一步只能让固定自动选择器使用同源 FASHN、Pose 可见性和竞争候选证据，先产出源图角色图，再对照冻结的可见衣缘与核心验收。只有之后的普通 Rust 0/±30 同参数输出同时满足真实衣侧响应、袖手电脑稳定和接缝正确，才算这张图的效果通过。不能输入上述手工矩形选 mask、仅保住白衬衫、把全部衣物冻结或临时减小请求幅度。

## 自动选择 V2 与第二图的反证

V2 从 Pose 骨段内三个采样点生成可见材料证据，改为每骨段需要连续两个命中，不再把肩部附近每个预测点都视为真实可见袖内点。它在 action-suit 自动选择了两袖候选；这项规则是在该图 V1 失败后提出，属于探索性修改，需要固定后验证第二图。命中连续点只证明候选与骨段有关，不能证明整个 mask 或 alpha 正确。

原图角色图和重新测得支持域显示：肩袖连接的遗漏点约 `(599,470)` 在本次 waist 编辑域外；但画面左侧前臂靠电脑的内缘残带约 `x188–222,y620–790` 仍进入了躯干 mask 与实际支持域，部分是袖边、部分是低分辨率分割外溢到亮背景孔。原有保护 mask 不保护整条衣袖。允许普通 0/±30 回放用来**暴露问题**，不等于源图角色验收通过。当前 V2 为 FASHN 衣物类减双袖，还没有完成原方案中的整个人物/衣物候选相交；不能把分类外溢当成确定的躯干。

第二图 side-fashion 对同一 JPEG 重新推理，canonical RGB 与旧图完全一致；审查者曾看过这张照片的手工层对照，因此它不是全新照片的视觉盲测。本轮仍在看候选之前，独立按 RGB 冻结了 11 个稀疏材料核心，未读取旧手工 mask：`/tmp/body-independent-20261119/side-fashion/frozen-source-evaluation.json`，SHA256 `7fbea3e95957159b2b0645b8d94bbebd4b6ff375ebe2abac7908c8593ce14c15`。

检查了该图全部 87 候选和必要的原尺寸图。独立外套与丹宁支持存在，粉色弯曲前袖与粉色胸衣仍合并。这里不仅是缺少单个袖候选：对每个冻结核心像素建立其在全部 87 masks 中的成员向量后，得到：

- 粉色躯干核心 408/408 像素与袖核心共享成员向量。
- 前臂袖核心 594/594 像素与躯干共享成员向量。
- 上臂袖核心 747/756 像素与躯干共享成员向量。

两个像素在所有候选中的成员向量相同，任何仅以这些 masks 为输入的布尔集合表达式都无法将它们区分。该结论不排除新增的 RGB、几何或语义模型信息，但排除了“只调这批候选的组合权重即可找到袖子”的主张。证据：`/tmp/body-independent-20261119/side-fashion/candidate-signature-ambiguity.json`。V2 在此图明确拒绝输出 torso 是正确的失败报告，不能据此宣布功能已可用，也不能回到逐图手调提示继续掩盖召回缺口。

## 最新模型是否能直接补齐缺失语义

Sapiens2 官方论文为 [arXiv:2604.21681](https://arxiv.org/html/2604.21681)，2026-04 发布；此次直接读了论文而非仅沿用旧 Sapiens 结论。§5 的 29 类是在上一代 28 类基础上增加 eyeglasses；它没有宣称输出衣服下面的分部运动归属。

**原论文 Figure 15 第一图提供了直接反证**：[交叉双袖蓝夹克示例](https://arxiv.org/html/2604.21681v1/appendix/images/seg/100005551_ss-photo-bucket.jpg) 的胸衣和两只交叉衣袖均着同一 Upper_Clothing 色，只有可见手/腕分别着手臂类别色。Figure 7 的短袖也保留衣物类别。由此不能因为 taxonomy 同时有 `Torso`、`Upper_Arm` 就认定能区分衣袖和胸衣；为这个缺口直接下载大权重没有证据支持。

[SAM3](https://github.com/facebookresearch/sam3) 的文本/示例概念条件和 [PartGLEE](https://github.com/ProvenceStar/PartGLEE) 的对象—部件层级，与衣袖身份问题更相关，但尚未在本图验证。前者官方依赖 CUDA 并有 Hugging Face 权重访问要求，后者具体袖类别及本机 CPU/MPS 可执行性仍需验证。不得把候选技术写成已经得到的效果。本次没有下载模型权重或执行模型。
