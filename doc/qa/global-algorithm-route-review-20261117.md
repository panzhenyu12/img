# 2026-11-17 全局算法路线与可用性缺口

结论：继续当前“源材料身份、运动权限、光学覆盖分离 + 连续形变 + 固定同源背景”的路线，不另造求解器。最新改善具有因果依据，但仍属于受限输入下的离线算法结果；整体未达到通用可用或逐功能 8 分。接下来最需要完成的是可重复调用的算法闭环及独立照片验收，不是继续在旧照片的同一处做微像素调参。

本次只审源码、已有成片记录与输入流程，没有重跑模型、编译、修改算法或接入系统。依据为 [当前验收范围](algorithm-progress-20261117.md)、[续审](algorithm-progress-20261117-continued.md)、[48 个脸部结果审计](face-source-context-review-20261117.md)、[身体内存合同](../func/FUNC-072-body-source-layer-memory-contract.md) 和 [验收目标](quality-targets.md)。

## 最阻碍可用的三个缺口

### 1. 好结果尚未形成普通 native 可重复调用的同一个算法

本次审查时，`engine.rs::apply_graph` 仍分别调用 `face::adjust` 和 `body::adjust`。脸部完整源上下文中的 `__physicalAlpha`、`__sourceMotionInterface`、`__sourceMovingAttachmentSupport`、`__sourcePlatePrior` 仍有 `cfg(test)` 分支；非测试构建把 `continuous_source_domain`、`keep_source_plate` 设为 false。因此，48 个候选结果不能被解释为普通 native 或当前应用已经拥有同样效果。

身体新增 `adjust_with_source_layers` 已是非测试算法代码，且已有真实衬衫回放；但入口仍为 crate 内部，普通 `apply_graph` 不消费它。调用由实验 harness 完成；该 harness 还固定使用本机依赖产物名和历史结果路径，不能视为任意新照片的一键算法验证入口。

另一项版本边界：`experiments/face-attachment-motion-20261110/face_pipeline.py` 的完整策略仍是 `complete-head-source-v2-attachment-plan-W10`，最后使用独立 field solver/sampler；新 48 图使用 `source-domain-continuous-v1`。前者可复用源准备，却不能把其整条 pipeline 的验收或刚性保证直接转移给后者。

**下一步**：通过窄的纯内存 native API 调用已验证代码，显式传入完整源上下文；保留旧入口兼容，不要求 Web 接入。先验证相同源/参数的新入口与已接受候选逐 RGBA 等价，再用新入口做新的照片验收。root 已开始这个迁移，但本记录不提前计为完成。

### 2. 已有照片大多是开发集，尚未证明固定策略能处理新输入

user、woman、dark、Lupita 及历史 holdout 已参与诊断和修复。多个档位、裁切和单控只能增加同一照片的检查范围，不能增加独立来源数。alpha 编码错误和附件许可遗漏修正是正确的合同修复，也证明输入适配是当前结果的必要组成部分；不能只保存成功 PNG，再把输入准备视为已自动解决。

本次未发现为通过回归而降低请求幅度的证据：身体新入口保持原场，脸部审计也明确检查了真实轮廓响应。但“当前几张没有新增破图”仍不是自然度、泛化或 8 分依据。

**下一步**：固定代码、模型、源准备规则和支持范围后，由独立审查者只看原图选照片；所有失败、拒绝、无效编辑均保留。任何看过失败后更换照片或专门改参数的结果都转入开发回归，不继续称盲测。源图、实际消费 alpha/B/权限、参数、程序和输出都保留哈希与生成命令，临时图片不入 Git。

### 3. 材料覆盖与功能范围仍有真实空缺

`tilted-shirt` 的 MEMatte 是 shirt-only：白衣外缘和内部衣纹改善通过局部复核，裙子探针的 alpha 仍为 0。该输入不能证明整人体收腰、裙子或独立袖子遮挡已经可用。身体的 `geometry_target` 保留部位驱动是正确的，但共享光学层本身不能区分前臂、躯干、两腿等真实遮挡层；运动保护和隐藏材料仍需由源准备提供。

脸部同样不能把所有后续问题归为曲线平滑：侧脸关键点失败、眼高的眼睑/眼球归属错误、复杂去人的缺失结构、白头/囊肿和大褶皱，都是尚未闭合的真实功能。已通过局部颜色和少数轮廓不能替代它们。

**下一步**：逐项区分“输入材料不成立”“请求没有执行”“形变不自然”“补全破坏结构”。只修改被证据指向的一层。不能用放大整体 alpha、冻结错误区域或减弱参数让失败消失；缺失的层明确拒绝或保持未支持，且这些拒绝仍计入覆盖缺口。

## 一条可执行的验收路线

1. **冻结可复现算法身份。** 完成 face/body 纯内存入口。同一份源上下文贯穿内部递归和正负参数，不通过测试编译选另一算法；先以现有少量已接受结果确认等价。显式坏输入必须报错，不能丢字段后静默跑旧路径。此步只做必要核心构建及定向验证。
2. **冻结一次源准备。** 对每张照片从原图生成源层；同一源的 `0/±30/±60` 共用 alpha/B/权限。记录 source 到实际消费值的往返一致性，避免再次出现 `[0,1]` 被按 `[0,255]` 解释或漏附件权限。源准备失败同样输出完整失败记录。
3. **先关闭两个具体功能。** 首轮以脸宽和收腰为目标，各选至少六张未参与调参的独立原图。脸覆盖正面、倾斜、三分之四、深肤色/暗光、发丝或眼镜、复杂背景；身体覆盖裸臂、普通衣物、手贴腰、斜姿、裙装、前层遮挡。固定支持范围，侧脸等已知缺口额外保留拒绝对照；不能通过拒绝全部困难输入把通用验收变绿。
4. **按完整照片判定。** 每张核对零值、双向实际轮廓变化、强度递进、保护区域、连接和背景；原尺寸整体外观为主，局部放大定位原因。任一声称支持的情况出现裂缝、断连、明显错误曲线、旧轮廓或无响应，该范围不通过。`±60` 作为强档单列，不能拿轻档结果代替。独立审查自然度和细节，不从通过率或测试数量换算审美分。
5. **通过后冻结，再推进其他功能。** 已通过照片只保留必要回归；为失败新增一个因果反例，修复后重跑受影响项，并用新独立照片检查泛化。依次处理眼高/其余五官、手臂腿部与遮挡、去人结构等账本缺口，不把两个代表功能通过写成一期全部完成。每次记录初始化与热运行时间；现有秒级形变、百秒级源准备尚不能称实时。

第一轮可接受的交付是“普通 native 入口、固定源准备策略、明确照片范围与失败清单下的脸宽/收腰算法可用证据”。这不是当前应用可用、所有功能达标或 8 分结论。应用接入等后续验收仍按用户既定顺序，在算法通过后进行。

## 原生接口迁移的特别注意

- `upper_width` 的递归及额头 `hairline` 的递归必须继续传递完整 typed source context；否则新入口仍会在内部丢回旧路径。
- 当前脸部 source plate 会在原配对后按权重应用 scene prior，并可用 `SceneLowerBound` 调整覆盖。它不是身体 API 中现成且不可修改的 `paired_background`。迁移应保留这段明确的源准备合同，或输入已冻结的最终 alpha/B 并证明输出等价，不能简单改名后重新夹 B。
- `JointFlexible` 只保证附件参与共同场，不保证耳饰刚性；旧 W10 的形状约束不能移植成新入口的文字承诺。
- 默认兼容路径可暂保留，但报告必须标明实际调用的算法入口，避免以后再次把离线候选的进展解释为用户正在操作的版本。
