# 第一期开发计划与交付对账

2026-10-13 算法与双端更新：人脸已采用论文 rigid MLS、独立脸/头发/耳朵/配饰层与多尺度 F/B 估计；分类覆盖仍不是真实 matting。身体非零调整必须有真实 subjectMask，已删除无分割的背景拉伸路径；partMask 接口已通，自动 Pose 尚未解决衣物/手/头发部位归属。皮肤采用有蒙版的 Fast Guided Filter。去人保留传统 exemplar，并实现浏览器 ONNX LaMa 与 Go→本地 TorchScript Worker 双端推理，参数 execution 明确选择处理位置。实际效果仍有失败，逐功能 8 分目标尚未达到；当前状态见 [最新验证](qa/current-validation.md) 和 [质量目标](qa/quality-targets.md)。

版本：v0.2 · 2026-10-12

## 目标与边界

按“先 Web + 后端、先做开源 Demo、先不考虑数据问题”的目标，实现独立于 AI 的手工图形修图链路：导入 → 标记区域 → 参数/画笔/网格调整 → 前后对比与历史 → 保存操作工程 → PNG/JPEG 导出。后端能够用同一 Rust 算法回放所有 Operation；AI 通过 MCP 生成可审阅提案。

`feature-list.md` 是完整产品功能目录，覆盖未来各种客户端与云端工作流，其P0/P1不等于本次Demo完成清单。本版明确记录 Demo 级算法、当前实装技术与尚未接入的增强，替换旧计划中的未实现技术描述。

## 完成标准

- API、AI、外网不可用时，已加载的本地页面仍可导入、手工调整、修复、撤销和下载。
- 已支持滑杆必须进入真实算法；对称仅在可靠语义下提供，未接入的 Pose 身高/腿长不显示；参数和操作能够保存、验证、回放。
- 各主要手工工具有浏览器实际操作与像素验证，不能只用构建通过作为功能验收。
- 同一PNG与同一EditGraph在WASM/native逐像素一致；JPEG需考虑编解码/颜色管理差异。
- 预览队列只保留最新参数，旧CPU任务可停止；导出保存独立快照，不被滑杆取消。
- AI临时预览不进入历史；接受可撤销；拒绝不改图；新手工编辑不能被旧提案覆盖。
- Makefile可构建、启动、停止、检查，真实结果写入独立func与QA文档。

## Demo限制与后续增强

旧计划提出的WebGPU/WebGL2、Tile/代理图、30FPS/6000×4000实时目标和多浏览器兼容验收尚未实现或完成测量。当前以CPU WASM/native + Canvas2D完成手工功能，32MP仅是资源上限，不能当作高性能承诺。

当前Face/Pose定位输出canonical关键点与特征/身体部位支持域。Face自动路径另用本地BiSeNet ONNX解析skin/hair/neck及头部alpha；Rust以真实内脸边界控制、完整head前景反采样和分层窄带填补，背景固定。Pose人体分割驱动腰/胯/四肢粗细；未定位、遮挡或无底层donor的案例拒绝或记录未验证，不回退全图模板。鼻子和五官按各自语义部位调整。衣物去褶皱目前是细纹弱化，严重褶皱/版型尚未实现。背景人物/杂物提供手工圈选与主体保护的exemplar填补，生成式背景重建尚未实现。

## 当前算法优先级

先打磨具体修图能力与真实样片效果：脸部轮廓和五官定位、皮肤与妆容、腰胯/四肢语义粗细、背景去除。此阶段不扩展云端账号、数据、商业化和 Agent 工作流。优先改善脸缘matting与分层底图、复杂背景补全接缝、身体/衣物像素解析，再增加多样样片验收。对账区分“进入像素算法”与“真实样片视觉质量”，逐参数有变化不能替代自然度验收。

没有账号、数据库、云同步、图库、RAW/TIFF/HEIF、16-bit/ICC、批量、完整PSD图层组、OPFS/IndexedDB、自动保存或PWA。工程JSON只含操作，恢复必须再次提供原图。这些完整产品需求仍保留在功能目录，未作为本期已完成项勾选。
