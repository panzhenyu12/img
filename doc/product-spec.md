# 人像美颜与图形修图产品文档

> 实施说明（2026-10-12）：本文包含长期多客户端/云端产品愿景。当前交付为 Web 手工修图 Demo 与 Go/Rust/MCP，数据系统、GPU 加速、全自动分割和生成式去人尚未纳入已完成范围；具体以第一期计划与 func/QA 对账为准。

版本：v0.1

## 1. 产品概述

本产品是一款面向人像摄影、婚纱摄影、写真、影楼和个人创作者的跨平台修图软件。第一阶段先交付 Web 端，聚焦人像美颜、五官调整、身形调整、衣物修饰、局部修复、图形变形和胶片模拟滤镜；后续再扩展桌面端和移动端。

核心原则是：

1. 不依赖 AI 也能完成完整的手工修图。
2. 不依赖网络也能打开项目、编辑和导出。
3. AI 是可选加速器，输出标准的参数、蒙版、图层或修复结果。
4. 所有美颜和变形都尽量非破坏，可随时调整、关闭和恢复。
5. Web 端支持高分辨率照片，浏览器根据设备内存动态降低缓存和并发。

## 2. 目标用户

### 2.1 商业摄影师和修图师

需要快速完成一组人像照片的统一调色、面部调整、磨皮、身形和衣物修饰。

### 2.2 影楼和工作室

需要参数预设、多人照片批量同步、原尺寸导出和团队共享。

### 2.3 个人摄影师和内容创作者

需要较低学习成本，通过滑杆完成脸型、五官、皮肤、身材和服装调整。

### 2.4 Web 端用户

需要在浏览器中使用鼠标或触控完成修图，网络不可用时仍可完成基础工作。

## 3. 第一阶段目标

第一阶段的目标是打通以下闭环：

```text
导入照片
→ 选择人物或手动选择区域
→ 调整脸型、五官、皮肤、身形和衣服
→ 手工修复与调色
→ 前后对比
→ 撤销和重做
→ 保存项目
→ 原尺寸导出
```

AI、人脸自动定位、AI 去人和云端批处理不属于第一阶段的使用前置条件，但数据模型必须为它们预留接口。

## 4. 产品信息架构

### 4.1 首页/项目页

- 最近项目
- 本地项目
- 云端项目入口
- 新建项目
- 导入图片或文件夹

- 恢复未完成项目

### 4.2 图库页

- 单图、网格、对比和参考视图
- 星标、旗标、色标
- 按编辑状态、导出状态、人物和标签筛选
- 显示原图、RAW、代理图和导出状态

### 4.3 精修页

- 中央画布
- 左侧图片缩略图和人物列表
- 顶部缩放、前后对比和显示控制
- 左侧工具栏：选择、画笔、修复、液化、变形、裁剪
- 右侧参数面板：脸部、五官、皮肤、头发、身形、衣物、调色

### 4.4 创意/图层页

- 选区和渐变
- 文字、形状和叠加元素
- AI 生成图层的后续扩展入口

## 5. 核心交互要求

### 5.1 参数化美颜

每个参数包含：

- 参数名称和当前值；
- 最小值、最大值和默认值；
- 作用人物或作用区域；
- 是否启用；
- 局部蒙版；
- 重置按钮；
- 从源图重新计算的能力。

例如瘦脸不能把上一次已经变形的图片再次变形，而应使用：

```text
原始图像 + 控制点/网格 + 瘦脸强度 = 当前预览
```

这样可以避免反复拖动滑杆导致画质损失，并保证滑杆回到 0 时恢复原图。

### 5.2 无 AI 的脸部调整

无 AI 时，用户可以：

- 手动标记脸部范围；
- 标记额头、颧骨、下颌和下巴控制点；
- 直接使用液化画笔；
- 使用网格控制点调整脸型；
- 锁定眼睛、嘴巴、头发和背景等保护区域。

AI 上线后，只负责自动提供这些控制点、蒙版和初始参数，不能改变底层编辑协议。

### 5.3 AI 调用与 MCP

AI 通过 MCP 工具调用产品能力，工具返回可预览的编辑提案；用户确认后才写入新的编辑版本。瘦脸、五官、皮肤、身形、衣物、修复和胶片滤镜都必须能映射为标准 `Operation`，并保留来源、模型、解释和请求 ID。AI 不直接覆盖原图，也不能绕过手工编辑、撤销和历史记录。

浏览器 WASM 负责执行图像算法，Go MCP Gateway 负责工具协议、会话、版本校验和调用 Rust WASM/native Worker。AI 服务不可用时，手工功能继续工作。

### 5.4 手工去除杂物

用户可以使用：

- 套索、矩形、椭圆、画笔选区；
- 修复画笔；
- 修补工具；
- 仿制图章；
- 内容感知填充；
- 图层蒙版。

AI 去杂物上线后，输出一个可关闭、可调透明度、可继续手工修改的修复图层。

### 5.5 画布性能

- 预览只计算当前可见区域；
- 使用 256、512 或 1024 像素 Tile；
- 使用 Mipmap 或多级缩略图；
- 笔刷只重新计算受影响的 Tile；
- 导出时再计算完整分辨率；
- 根据设备内存动态控制 Tile、GPU 纹理和撤销缓存；
- 移动端使用磁盘临时缓存和检查点，避免一次性展开整张 100MP 图片。

## 6. 非功能需求

### 6.1 离线能力

离线状态下必须支持：

- 打开本地项目；
- 手工美颜和图形调整；
- 图层、蒙版和历史；
- 保存项目；
- 原尺寸导出。

AI 任务失败、网络中断或模型不可用时，不得锁定画布，也不得影响手工编辑和导出。

### 6.2 颜色和精度

- 内部合成优先使用线性光 float16；
- 支持 8-bit、16-bit 和 HDR 资源；
- 显示和导出分别进行 ICC 色彩转换；
- 至少支持 sRGB、Display P3 和常见相机色彩配置；
- 不能在每个操作之间反复转换到 8-bit。

### 6.3 可恢复性

- 编辑事务具有明确开始和结束；
- 每次大操作可撤销；
- 崩溃后可恢复最近一次保存；
- 导出失败不破坏项目；
- 项目格式有版本号和迁移机制。

## 7. 技术架构

### 7.1 第一阶段 Web 客户端

第一阶段使用：

- React + TypeScript + Vite；
- WebGPU 主渲染，WebGL2 回退；
- Web Worker + OffscreenCanvas 处理大图；
- IndexedDB/OPFS 保存离线项目、Tile 和代理图；
- Rust/WASM 图像核心提供参数化变形、蒙版、画笔和基础滤镜。

后续桌面端可以选择 Qt 6/QML，移动端可以选择 SwiftUI/UIKit 和 Jetpack Compose；这些客户端继续调用共享图像核心。Go 用于服务端和任务编排，不进入浏览器每帧像素循环。

### 7.2 共享图像核心

由于第一阶段先做 Web，建议使用 Rust + Cargo + WebAssembly/wgpu 作为浏览器端图像核心；后续原生端继续复用同一套几何、蒙版和参数模型。RAW、16-bit、HDR 和高质量最终渲染可以由 Rust/C++ Render Worker 处理，Go 负责调度，不进入像素热循环。

```text
ImageCore
 ├─ DocumentModel       项目、图层、蒙版、调整节点
 ├─ PixelEngine         像素算子和颜色运算
 ├─ WarpEngine          液化、网格和人体变形
 ├─ MaskEngine          选区、蒙版、羽化和保护区域
 ├─ RenderEngine        Tile、Mipmap、GPU 和 CPU 回退
 ├─ ColorEngine         ICC、线性光、色彩空间和胶片模拟
 ├─ FilterEngine        LUT、曲线、颗粒、暗角、辉光和 halation
 ├─ RawEngine           RAW 解码和相机参数
 ├─ HistoryEngine       撤销、重做和检查点
 └─ FileEngine          项目、导入和导出
```

### 7.3 GPU 方案

推荐采用 GPU 后端抽象：

- macOS/iOS：Metal；
- Windows：DirectX 12；
- Android：Vulkan；
- 简单滤镜可以使用 Skia Shader；
- 高级液化、Tile 合成和导出算子保留原生 GPU 路径；
- GPU 不支持时提供确定性的 CPU 路径。

Skia 可以承担 Canvas、采样、混合和基础滤镜，但不会自动解决 RAW、ICC、Tile 调度和非破坏编辑模型。Qt Quick Scene Graph 负责 UI 合成，不能直接等同于照片处理核心。

### 7.4 胶片模拟滤镜

滤镜不是一次性覆盖像素，而是一个可重算的调整节点。一个胶片模拟预设可以由以下部分组成：

- 色彩矩阵或基础色相偏移；
- RGB 或分通道色调曲线；
- 高光、阴影、黑位和褪色；
- 3D LUT 或等价的颜色查找表；
- 胶片颗粒，区分亮度颗粒和色彩颗粒；
- 暗角、辉光、高光柔化和轻微 halation；
- 强度、混合模式和局部蒙版。

浏览器使用低分辨率预览和 GPU shader，后端导出使用同一份参数在高分辨率重算。第一期采用自定义风格名称，例如“高饱和高反差”“粉彩人像”“复古颗粒”和“夜景冷色”。发布时不直接使用相机厂商商标、官方 LUT 或未经授权的配置文件。

### 7.5 图像算法

- OpenCV：几何、颜色和部分 CPU 算法；
- LibRaw 或同类方案：跨平台 RAW；
- OpenColorIO/LittleCMS：色彩管理；
- OpenEXR：HDR 和半精度资源；
- 自研 Mesh Warp：脸型、五官、身形和衣服变形；
- Heal/Clone/Patch：皮肤和杂物修复；
- ONNX Runtime：后续接入 AI 模型。

### 7.6 项目数据模型

项目核心对象包括：

```text
Project
 ├─ Asset              原始文件、缩略图、代理图
 ├─ Document            画布信息和颜色空间
 ├─ Layer               图层和图层文件夹
 ├─ Mask                灰度蒙版和选区
 ├─ Adjustment          调色和美颜参数
 ├─ Warp                控制点、网格和位移场
 ├─ History             撤销历史和版本快照
 └─ RenderCache         Tile、预览和导出缓存
```

AI 后续只允许输出以下标准对象：

- 调整参数；
- 控制点或变形网格；
- 灰度蒙版；
- 普通像素图层；
- 带蒙版的修复图层。

这样 AI 和手工工具能够共用撤销、图层、导出和同步机制。

## 8. `Compositor` 的使用边界

`Compositor` 可以作为 Mac 端原型和本地编辑内核参考，适合复用或借鉴：

- 图层、蒙版、调整层和历史；
- 液化、画笔、修复和仿制图章；
- Metal/Core Image 渲染；
- Tile 缓存和 CPU 回退；
- PSD、RAW 和项目保存。

正式跨端产品不应直接继承它的 SwiftUI/AppKit 和 macOS 专用 I/O 架构。其 `.comp` 文件也不应成为云端标准格式。云端应使用跨平台的 `Project + Asset + EditGraph`，并允许本地客户端导入或导出 `.comp`。

## 9. 版本规划

### M0：编辑内核

- 导入、保存和导出；
- Tile、缩放和 GPU 预览；
- 图层、蒙版、撤销；
- 画笔、修复、仿制图章、液化；
- 基础调色。

### M1：基础美颜

- 手动脸部控制点；
- 瘦脸、下颌、下巴、眼睛、鼻子和嘴巴；
- 磨皮、祛痘、肤色和局部修复；
- 脖子、肩膀、腰腹、手臂和腿部调整；
- 参数化重算和局部保护。

### M2：高级人像和衣物

- 头发、妆容、牙齿；
- 身形比例和姿势；
- 衣服祛皱、颜色、版型、裙摆；
- 鞋子、手部和配饰；
- 预设、参数复制和批量应用。

### M3：AI 与云端增强

- 自动人脸和人体关键点；
- 自动皮肤、衣服和背景蒙版；
- AI 去人和去杂物；
- AI 初修和参数推荐；
- 云端项目、跨设备同步和异步任务。

## 10. 第一阶段验收标准

关闭所有 AI、断开网络后，用户仍然可以：

1. 导入一张高分辨率照片；
2. 手动选择脸部或身体区域；
3. 使用参数或液化工具调整脸型、五官和身形；
4. 对皮肤、头发、衣服进行手工修复；
5. 使用图层、蒙版和调整层；
6. 使用撤销、重做和局部重置；
7. 保存项目并重新打开；
8. 导出原尺寸图片。

## 11. 主要风险

- 高分辨率图片在移动设备上的内存压力；
- GPU 预览和 CPU 导出结果不一致；
- 变形后背景线条和衣物边缘出现穿帮；
- 皮肤过度磨皮导致纹理丢失；
- RAW、ICC、16-bit 和 HDR 的跨平台差异；
- Qt、Skia、RAW 编解码器和模型的许可证合规；
- Compositor 主分支持续变化，若使用应锁定稳定 tag 或 commit。
