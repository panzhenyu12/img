# FUNC-074 源虹膜测量约束的眼宽调整

2026-11-18：修复公共调用入口。已有的虹膜材料保护算法此前只在内部调用测试中成功；公共 `feature.adjust` 拒绝 `eyeGeometry`，因此外部请求无法使用它。这不是前端构建或部署问题。

## 行为合同

眼宽改变眼角及周围眼睑，源眼裂内实际可见的虹膜不因眼宽单项被拉伸。与大眼组合时，大眼仍可改变虹膜大小。眼角轨迹碰到虹膜采样保护范围时明确拒绝，不能静默缩小强度或返回原图冒充成功。眼高、眼睑开合仍未完成；当前拒绝它们的非零请求，避免导出已知虹膜纵向拉伸效果。

`feature.adjust.params.eyeGeometry` 可包含 `leftEye`、`rightEye`，每项为：

```json
{"iris":{"center":{"x":0.3,"y":0.4},"boundary":[{"x":0.32,"y":0.4},{"x":0.3,"y":0.38},{"x":0.28,"y":0.4},{"x":0.3,"y":0.42}]}}
```

坐标相对完整源图归一化；边界四点依次是投影的右、上、左、下，不按屏幕横纵大小重新排序。每只测量眼必须对应 `semanticMasks` 中的眼裂 polygon。显式提供测量时，非零眼宽涉及的两眼不能缺一只测量，避免左右混用算法。未知键、非法坐标、空对象、退化投影等被拒绝，零值也校验输入。参数只允许用于 `feature.adjust`。

没有 `eyeGeometry` 的旧输入仍保持兼容路径；这不代表旧眼宽的虹膜保真已经修复。测量可以由检测器或人工提供，核心不依赖模型。参数的结构合法不能证明检测到了真实虹膜。

## 验证

`core/image-core/tests/eye_material_contract.rs` 通过普通 `apply_graph_json` 检验：双向眼角响应、非空可见虹膜纹理逐字节不变、移除测量的旧路径确实改变虹膜、眼宽与大眼组合、零值恒等、坏输入拒绝、眼角与虹膜冲突拒绝。新增测试先复现公共入口拒绝，修复后 5 项全部通过。

`experiments/eye-material-public-20261118/replay.py` 复用两张同源、hash 绑定的 MediaPipe 478 点测量，调用普通 native `image-render` 的 0/±30/±60 眼宽，10 张输出成功，两项零值逐字节恒等。源图不重采样，不运行新模型，不启用测试专用分支。原尺寸/两倍眼部对照留在本地 `test/results/eye-material-public-20261118/`，不上传照片。

本次未接 Web/WASM，未重建其他服务。眼镜遮挡、真实闭眼、测量误差与更广泛样本仍是独立验收项，不能由这两张照片推导出全功能可用或 8 分。

独立实拍复核接受本批两来源、四非零档的眼角响应和接点连续性。可见虹膜交集、眉/唇/牙区域逐RGBA不变；+60内眼角过渡触及17/20个鼻根polygon像素，不能称鼻部完全不动。见[独立审查](../qa/eye-width-public-independent-20261118.md)。
