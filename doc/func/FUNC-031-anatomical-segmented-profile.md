# FUNC-031 五官高度驱动的脸部目标曲线候选

状态：隔离算法已实现，数学回归通过；实片未证明自然度收益，不接入默认路径。日期：2026-10-26。

关联需求：FACE-005、007–010、012、014–016、021–024。目标是分别表达脸宽、太阳穴、颧侧、下颌、下巴和额头的调整，不把一个脸宽公式当作所有部位的形状模型。

## 实现与边界

代码为 `core/image-core/src/face_profile.rs` 与 `face_profile_normal.rs`。仅在 `cfg(test)` 下编译。`face.rs` 中的回放选择分支同样只在测试中存在；Web、Go、MCP、公用 operation schema 均未增加此功能。

沿用旧算法已有的双眼方向坐标系，从眼、鼻、唇多边形中心推导高度节点；缺少语义时用几何比例代理。它们不是颧骨或下颌角的解剖真值。标量权重使用五次插值，不能据此声称整条目标曲线 C²、无自交或美观。

本轮修正候选的四项错误：

- 测试曾将绝对图像边界当成局部坐标边界，导致中脸零响应；坐标合同已明确。
- 原候选漏掉 `forehead`、`foreheadWidth`、`chin`。现保留独立长度控制，宽度控制只沿脸的横轴作用，不附带缩短下巴。
- 法线使用有向面积判绕序，并按固定物理弧长取两侧切向，避免凹口方向反转和非均匀顶点采样造成响应不同。
- 眼、鼻、嘴高度不合法时显式报错，不排序伪造解剖关系，也不让 clamp 的上下限颠倒导致崩溃。

## 用户行为、协议与运行

最终用户行为仍是分别拖动已有脸型滑杆。本候选只提供离线回放，未交付新的前端或后端功能。对应 operation 仍为 `face.adjust`，数值仍为 `adjustments` 内的 −100..100。

仅内部测试可用 `experimentalFaceProfile="segmented-lateral-v1"` 选择候选；这不是公用参数，正式图验证器继续拒绝它。不得将该测试参数发给 Web、API 或 MCP。

回归：`make quality-face-profile`，12 项通过，覆盖零值、正负方向、强度、镜像与旋转、长度/宽度隔离、无效语义、凹轮廓、绕序、非均匀细分、重复点和退化几何。

## 实片验收

三张缓存图分别运行 ±60。候选的请求面积变化只有旧算法的 63.5%–69.0%，因此另以旧算法 ±38.09、±39.99、±41.42 做相近面积对照。面积误差小于 0.000011 个百分点，但不是逐点目标相同。

用户图脸颈残片和 dark 耳侧/眼侧硬痕仍在。未证明更自然，不能用较小幅度冒充优化。保留此模块用于可复现诊断，不替换旧目标生成器。详见[实片记录](../qa/face-segmented-profile-20261026.md)。

完成标准仍包括：各滑杆方向/部位正确、相近改变量下曲线更自然、完整五官/附件与背景保护、无新增接缝，以及未参与开发的多骨相和遮挡样片验证。本轮未达到这些完整标准，也不恢复瘦脸评分。
