# FUNC-058 源耳饰约束与耳颊材质诊断

日期：2026-11-12。状态：算法实验；尚未通过整体瘦脸可用性验收。

## 已确认并修复的错误

`experiments/face-attachment-motion-20261110/geometry.py` 使用 source-forward
场，但原附件约束调用了面向 inverse 场的扫掠支持适配器。它把从源位置到
目标位置途中的其他材质网格节点也绑进刚性组。滑杆位移仅变化 0.00002px
就可能新增两个节点，与无关固定点发生冲突。

新增 `--attachment-domain source`，仅约束源饰品/接触点及其源像素采样足迹。
源支持与参数、方向无关；保留 `swept` 作为旧对照。测试覆盖采样足迹、微小
请求变化及固定点冲突。此修改未进入应用默认算法。

在同一用户原图、缓存、求解器和目标下，四档源刚性组节点恒为 67/63；旧扫掠
组随参数变化。+100 的全轮廓请求实现率由 .7516 到 .8330，±30 下颌实现率
约 .9996。强档下颌仍只有 .7359，说明此修复不能解决下颌曲线的剩余问题。

## 耳廓共旋实验的结论

`face_bounded_field.rs` 增加可选的局部 SO(2) 共旋材料项；`ear_strain.py`
按源耳朵的实际覆盖面积积分，排除冻结区、已识别头发/五官/饰品。它允许旋转
与平移，避免把所有方向导数限制到 .10 的做法。

真实用户图 −100 左耳压扁有局部改善，但右耳前暗弯线仍在；第二张深色人像
响应与局部压缩指标反而变差。W10 一档求解约 11.7–17.6 秒，未达到交互要求。
因此本轮不采纳为默认。合成测试和能量下降不能替代成片验收。

2026-11-13 增量：dark 右耳内部的错误 hair 标签经独立源 RGB 声明纠正后，
实际耳材质积分域改变。在这一新域重试同一 W10，±30 耳内槽的斜扁和挤压
明显减轻，脸颊/下颌仍有有效变化，接受单图局部保形改善。该结果不撤销
旧错误域上的失败，不是自动类别修复，也不设通用默认。源角色、完整重建
和成片见 [耳内纠正回放](../qa/face-dark-ear-interior-correction-20261113.md)。

## 耳颊内部假透明谷修正

右耳前深弯线沿源 skin/ears 类别交界分布。`max(skin, ears)` 在两种不透明
材质的类别过渡处可形成约 .5 的谷；当前源 alpha 也保留了这条谷。残差合成
将其中一部分解释为深色背景，移动后使原本柔和的内部阴影加深。

不能直接把所有语义置信度相加当物理 alpha；细尺度耳类别与粗尺度皮肤类别
可能来自不同推理。独立候选 `face_internal_interface.rs` 现要求额外的源图
不透明内部声明，缺省精确 no-op。声明不能由本算法的选点或输出反推。
在声明范围内还需满足：

- 同一连通皮肤/耳朵材料内，距已观察外缘至少 3px 的类别置信度谷；
- 4px 内两侧已有不透明皮肤和耳朵种子，且源路径不跨越头发、饰品、冻结区；
- 原 alpha 与类别谷一致。类别已经饱和、但颜色估计确实降低 alpha 的样点不改；
- 两侧种子必须有明确的类别支配关系；两种 parser 都高置信的锚点不算接口证据；
- 显式提供的物理 alpha 始终优先，不执行类别推断修正。

候选只继承两侧较小的已知不透明 alpha，不改源 RGB、背景 B、几何或目标。
这是有条件的源材质假设，不是从语义概率恢复物理真值的普遍保证。

最初无额外声明的候选修正用户图 188 个源样点。沿用相同 `attachment-source-domain-baseline`
inverse 场回放 ±30/±100，观察到耳垂前新增深线减弱，原耳部阴影和耳廓纹理
仍在。四档均无冻结区改动、无浮点越界、零请求精确重构。完全落在修正源材料
内的输出与直接源 RGB 传输的 MAE 由 2.14–7.46 降为 0.008–0.018 字节；
该数值仅验证多余背景混入被抑制，不能用作审美分数。

最初 Python 9 项行为测试通过，覆盖已知不透明 RGB、深浅背景、真实半透明外缘、
保护障碍、显式 alpha 与不合法参数。Rust 独立模块 8 项对应行为测试通过，
先观察不透明颜色回归失败，再实现修正；真实 f32 源证据与 Python 的 188 个
alpha 修正逐位一致。只编译此 std-only 模块和原生小工具，未构建整个项目。

独立 woman 样本缺少耳语义，因此精确 no-op；dark 样本虽有耳语义，也未满足
内部谷条件，因此精确 no-op。两者仅证明没有误改，不能说耳部修复已跨图验收。
Rust 模块未导入应用默认管线，实验入口为
`experiments/face-attachment-motion-20261110/internal_interface.rs`。

后续独立审查补充了真实 AA 细缝反例，证明上述语义条件仍无法充分区分物理
透明与类别误差，并修复 Python 距离变换对裁剪边界的处理。当前 Python 内部
接口 13 项、来源验证 10 项、Rust 10 项通过。详见
[内部接口独立审查](../qa/internal-interface-independent-audit-20261112.md)。
旧 188 点结果只保留为历史候选观察，不能作为当前自动路径。

重新查看原图后，助手用源 RGB 坐标手工圈定右耳前的 836 个不透明内部像素，
避开外缘和耳饰；它不是用户标注，也不是盲评或物理真值。使用该独立于选点
计算的声明，当前算法只修正 162 个点，Rust/Python 逐位一致。同 inverse 的
±30/±100 四档仍减轻额外暗线，变化全部在对应源样点的传输足迹内；强档
耳廓拉长/倾斜未改善。见[声明后独立复核](../qa/internal-interface-declared-independent-review-20261112.md)。
声明和回放在 `internal-interface-source-review`、`internal-interface-declared-cache`、
`internal-interface-declared-replay`；未从旧 188 点生成声明或扩大 ROI 凑点数。

## 强档几何幅度实验

相同目标和保护下，统一导数界从 .24 调至 .35 能使用户图 +100 下颌响应从
.736 提升至 .985，但嘴侧压缩增加。woman/dark 的 +30 局部转角误差却变大：
固定皮肤控制点不动，邻点移动更多。故保留可选实验参数，不采用通用新默认。
当前继续修复源材质固定约束的作用范围；不能用扩大幅度掩盖错误固定点。

## 固定材质与静止下层的复核

`source_motion_roles.py` 将源 matte 中严格 `alpha=0`、源 RGB 与 B 完全相同、
`known_layer=2` 且没有保护/刚性/衣物/供体禁令的静止头发下层识别为空前景。
它只允许去掉这些位置的前景速度锁，不改变源图层或输出冻结。woman ±30
全轮廓响应 .89074→.90519，视觉差异小；不能当作整体质量跃升。

有界求解器新增可选 `fixed_points`，直接约束双线性场在源中心的位移等于零；
adapter 按单元行空间压缩，解后重新核验全部原始中心。它避免将一个源固定点
直接升级成四个固定顶点，但相邻满秩单元仍会锁住共享顶点。在 woman ±30
单独启用时，PNG 与旧 baseline 完全相同；组合空前景下层修正后，全响应仅
到 .90776，下颌响应 .76384。这个候选没有解决主要层边界问题，不设为默认。

中心固定不保证整片插值足迹固定。测试用红色单像素条给出明确反例：中心不动，
邻近像素仍可被红色污染。真实组合的半像素足迹最大位移 .0414px；报告公开此
限制，而不是只用中心残差宣布保护成功。

进一步核对修正了上述诊断边界：woman (407,534) 的原 graph skin=.049、
hair=.593，trace alpha=.298 且 frozen=true，但原 graph 不是实际用于 trace
的完整语义状态。`face_upper_width::promote_interface` 会主动把邻发并入
共同移动材料；因此邻近原 hair=1 而 trace alpha=1、可动，并非 matting
错误的充分证据。实际 prepared masks、固定点来源和共同域连续性仍在审计。
撤回“源分解错误地把静止头发放进前景”的确定性归因，暂停人工后发清空候选。
