# FUNC-086：眼部连续材料笔划

2026-11-19。Rust 原图算法入口已支持连续细笔划，减少手工材料说明的坐标量。它不是新自动睫毛识别，也没有改变眼睑运动场、已有材料估计或开放通用眼高功能。

## 算法行为

`core/image-core/src/eye_source.rs` 的 `EyeMaterialShape` 新增 `polyline`：若干原图 pixel-index 点与一个正半径，组成连续线段胶囊的并集。选择胶囊内的源像素中心；它表示类别走廊，不能当作 alpha、羽化或重绘强度。支持 `ocularAnchors`、`movingLashSupport`、`unknown` 三种既有角色。

每段仅遍历自己的边界框，重复内部点不会产生除零。少于两点、所有点重合、非有限值、半径非正、走廊离开原图或未选中像素均拒绝。眼部域、类别冲突、跨眼归属、源绑定和实际逆采样 unknown 检查继续沿用原规则。

```json
{
  "shape": "polyline",
  "points": [
    {"x": 676, "y": 375}, {"x": 676, "y": 376},
    {"x": 673, "y": 381}, {"x": 673, "y": 382}
  ],
  "radius": 1.3
}
```

示例属于已核对的特定原图，不是其他照片的默认坐标。普通 `eye-closure --materials` 可直接解析，Python 历史实验格式没有同步增加此形状；调用者不要将新 Rust JSON 送入旧 Python runner。

## 源与成片验证

两项新公开入口行为测试先失败后通过：连续笔划中间的可见高光保持且眼睑仍运动；未知线条中间的实际反采样依赖会被拒绝，非法走廊不能进入源准备。`eye_closure_source` 合计 5 项通过。

makeup 真实细睫毛原来用 8 个半径 1.3 的离散印章说明，共 26 个 moving 像素；本轮先试两个端点。两点走廊仅覆盖 24 像素，虽然整眼宏观相近，但独立细看发现梢端 `(672,381)` 留在原位。该版本**拒绝**，不以仅 7 个差异像素为理由放行。

随后根据原来源图标注保留根部和梢部两个弯折，改为 4 点、半径不变。新连续走廊与原 8 印章的 26 个源像素逐一相同，其他眼球标注和供体不变。普通原图重新准备后，`0/−15/−30` 的全部 RGBA 和 inverse 场均与此前已独立验收的八印章版本逐字节相同；零值仍精确保持。26 个移动像素全部得到估计，原 13 个颜色模型不确定像素仍须保留。

收益是同一已确认材料从 8 个中心坐标减为 4 个顶点，保持已有成片效果；不是“少点就自动分出睫毛”，也不能增加审美分数。两点失败、四点修正分别保留在本地 `native-v1/material-line-r1`、`material-line-r2` 及对应 `makeup-line-r1/r2`。详细独立结论见 [眼部记录](../qa/eye-rust-material-route-20261119.md)。
