# FUNC-048 眼睑开合、眼球材质与像素覆盖

状态：**隔离算法候选；未进入主线；未达到可用或 8 分验收**。本轮只修改眼高实验，没有构建、接入或部署 Web/后端/MCP。正向开眼需要原图没有观察到的虹膜/巩膜，当前不生成伪完成结果。

## 原问题和语义

最终 eyeTilt V2 清洁源作为基线，用户照片 `eyeHeight ±30` 的虹膜局部纵向比例约为 0.917–0.918 和 1.089–1.090；眼角最大移动 0.126 px。把整个眼球压扁/拉长不能等同于眼睑开合。

闭合应该保持仍可见眼球的材质和几何，让眼皮遮住一部分旧眼球。目标按每个眼轴截面的上下睑间距缩放，比例 `exp(0.3 × amount / 100)`；眼角保持固定。构造时使用上下睑所有共同横坐标断点，不能仅变换原顶点，否则会漏掉对侧眼睑的折点。非单区间轮廓拒绝处理。

## 本轮实做

1. 复现并否决“像素中心二值归属 + 双线性采样”：用户强闭合下眼睑出现台阶；旧混合 RGB 被误当作纯眼皮运输。独立半像素反例的线性颜色误差为 17.5/255。
2. 实现多边形与像素方格的精确面积覆盖，在线性 RGB 中保留源眼球残差，闭合后按可见区域重新合成。没有对二值蒙版做模糊来掩盖台阶。
3. 修复独立审计发现的共同断点遗漏，以及眼角“像素有覆盖但中心超出眼轴范围”时把混合色作为纯前景的问题。两处修正均经小反例独立复核。
4. 增加面积一阶矩的研究参考：在已知局部线性眼球纹理梯度时，积分真正保留下来的像素子区域，解决简单残差缩放对亚像素渐变的错误。随后仅用源图完整可见、同一材质标签的邻域估计受限梯度，回放用户实拍 -30/-100；支持不足、睑缘和虹膜边界均保留未知。

5. 将单一眼皮前景拆为上睑、下睑两组覆盖与颜色。对应侧原 RGB 供体分别估计，9×7 异色上下睑反例从错误 0.625 修正为真值 0.5；用户实拍只出现少量像素修正，未证实自然度提升。

实验源及汇总：[eye-height-layer-coverage-20261029](../../experiments/eye-height-layer-coverage-20261029/README.md)。无照片、关键点、原始 RGBA 或蒙版进入实验目录。

## 还没有解决

- 语义眼裂多边形不是光学 alpha。所谓“眼皮侧供体”仍由语义几何筛选，不能证明其中没有睫毛、虚焦混色或分割误差。
- 最终 246 个边缘混合像素中，79 个需要把前景估计投影到颜色可行区间，最大修正 0.132（归一化线性 RGB）。这保证分解数值合法，**不证明纯前景或透明度正确**。
- 残差按覆盖率缩放假设保留子像素眼球均色不变。独立反例已经证明该假设会失效；一阶矩候选改善已知线性梯度，实拍只产生小范围（最大5/255）修正，尚无独立视觉收益。真实梯度和光学覆盖尚未可靠估计。不能用已知真值的合成测试宣称恢复了真实睫毛/虹膜边界。
- 单一 F/Fnew 不能表达同一像素里的异色上下睑。独立双睑候选已经修复该表示错误，且实际侧别供体反例通过；但真实上下睑的光学 alpha、纯色供体和睫毛细节仍未知，实拍暂未确认可见收益。
- 开眼显露的未知表面与闭合是两个问题；当前没有完成纹理恢复，也没有将未知区域压扁拉长来充数。

下一步先做原 RGB 光学边界及亚像素材质估计，再在独立实拍、妆容和不同眼睑条件下验证。主线旧 `eyeHeight` 的虹膜拉伸问题仍标记未解决，不能自动以该实验替换或验收。
