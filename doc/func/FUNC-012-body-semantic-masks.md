# FUNC-012 身体语义区域与局部身形调整

状态：语义宽度算法与性质测试已接入，多图自然度尚未全部通过；见 [身形批量](../qa/body-multisample-review.md) 与 [算法验证](../qa/algorithm-validation.md)。

## 目标

为身形、腰部、胯部、手臂和腿部调整提供可回放的 Pose 关键点与独立多边形蒙版，避免矩形选区把背景一起变形。功能在浏览器本地运行，没有 MediaPipe 时仍可使用手工矩形、套索或多边形选区。

## 操作协议

`body.adjust` 的 `params` 支持：

- `region`：当前语义区域的归一化包围盒。
- `mask`：由 Pose 关键点生成的 polygon 蒙版，默认羽化 8。
- `landmarks`：最多 128 个 `{x,y}` 归一化源关键点，用于 Rust/WASM 回放。
- `bodyPart`：`full-body`、`torso`、`waist`、`hips`、左右上臂/前臂/大腿/小腿。
- `subjectMask`：可选人体分割 alpha，`{shape:"raster",width,height,data:[0..255]}`，全图归一化坐标；数据长度为 width×height，协议最大 512×512，浏览器保持长宽比缩至最长边 256。
- `adjustments`：语义部位已支持的肩宽、腰围、腹部、胯宽、手臂/前臂、腿部/大腿/小腿粗细参数。身高、腿长、脚踝、体态等参数仍保留在旧手工区域协议，但未接入 Pose 语义算法。

同一人物的不同身体部位有独立的 mask 和 landmarks，可分别创建操作图层；切换区域会更新当前调整层的范围。

## 检测与蒙版

`apps/web/src/core/landmarks.ts` 使用 MediaPipe Pose Landmarker Lite 的 33 点结果：

- 肩（11/12）、肘（13/14）、腕（15/16）生成左右上臂、前臂 polygon。
- 髋（23/24）、膝（25/26）、踝（27/28）生成左右大腿、小腿 polygon。
- 肩髋四点生成躯干，中心线附近生成腰部和胯部 polygon。
- 有效 Pose 点凸包生成全身支持选区；关键关节低于 0.5 visibility 时跳过对应部位，完整全身要求主要四肢可见，保存原 33 点索引顺序。

MediaPipe Pose 启用 `outputSegmentationMasks`，每个人的分割结果保存为独立 `subjectMask`，保留双腿和手臂间隙。概率 0.35–0.65 映射为 alpha；读取后关闭模型资源。部位 polygon 是几何支持域，有分割时以中心放大 1.5 倍，给轮廓移动留出空间。腰/胯自动冻结双臂与手掌，躯干冻结前臂/手掌，避免收腰牵动交叉抱胸的手；冻结是按可见 Pose 骨骼和手指构造的保守画笔范围，仍不是遮挡部位像素解析，用户可手工修正。polygon 羽化覆盖为 0 的区域保持原图；主体 alpha 不作为最终输出裁剪。模型漏检时仍可手工选区。

## 语义形变算法

`body.rs` 在像素坐标计算轴向与横向距离，以正确处理照片长宽比。单侧肢体以近端关节到远端关节为轴，半径由实际 polygon 顶点在法线上的投影求得；腰部以肩中心到髋中心的方向、当前腰部 ROI 为支持域；胯部的左右髋点作为横截面，轴沿其垂线贯穿 ROI，因此两髋位于同一高度也能正常生效。

每个粗细参数沿独立纵向区间作用于轮廓带，中轴、关节端点和选区边界的位移归零。前臂可叠加 `arms` 与 `forearms`，大腿可叠加 `legs` 与 `thighs`，小腿可叠加 `legs` 与 `calves`；不会用第一个非零参数覆盖其他参数。`full-body` 依据 33 点中的肩髋及 8 条肢体段分别构建局部效果，不把身高、腿长解释为变瘦。

有 `subjectMask` 时使用独立前景路径：

- 沿骨骼法线扫描连续主体跨度，用首个背景交叉和中值估计部位真实半径。
- RGB 与前景 alpha 一起反采样，透明背景 donor 不贡献颜色；中央轴与关节端点保留，人物轮廓可以跨过原位置。
- 背景不参加形变，收缩后仅新露出的窄带使用现有传统 inpaint 修补；原主体与冻结像素不能作为背景 donor。
- 露出连通区域无法获得非保护背景时返回明确错误；避免用主体颜色冒充背景。
- 无 `subjectMask` 时保留旧局部逆采样路径，不能把它宣称为人物背景独立重塑。

Web registry 提供 `bodyParametersFor(bodyPart)` 与 `bodyPartDescription(bodyPart)`，语义区域界面只显示上述已实现参数。全身预览建议使用单独部位进行精调。

## 手工与 AI 共用

自动检测只负责提供区域和 landmarks，参数仍由前端滑块或 AI/MCP 写入同一 `body.adjust` 操作。保存工程后重新载入，`bodyPart`、`mask` 和 `landmarks` 可独立回放。Rust 校验会拒绝未知 bodyPart 或不在允许范围内的关键点。

## 验收

- Web 构建：`cd apps/web && npm run build`
- Rust 校验与渲染：`cargo test --manifest-path core/image-core/Cargo.toml`
- `body::tests`：水平胯点在 ROI 内正确产生正负收放；倾斜大腿 polygon 的投影半径与中心轴正确；组合腿部与小腿参数都生效；全身 `height/legLength` 不导致收窄；左右上臂/前臂/大腿/小腿与腰胯的粗细参数均有局部效果。
- 分割路径合成测试验证正值真实收窄、负值真实扩张，格栅背景原像素不位移、扩张前景不染背景颜色、保护半边不变、无背景 donor 明确报错。
- 生成一张 Pose 检测结果后，检测列表应显示“人物 1 · 腰部”“人物 1 · 左小腿”等语义项；点选后选区为 polygon。
- 新增身形图层后，工程 JSON 同时包含 `bodyPart`、`mask.shape = polygon` 与 `landmarks`，mask 外背景像素不参与局部合成。

## 当前限制

Pose 分割提供模型预测的人体像素 alpha，仍不是皮肤/衣物/各身体部位解析，也不是精确 matting；遮挡、宽大衣物和多人重叠可能分错。低分辨率软边可能带原照片混合色，传统窄带背景延拓无法恢复复杂建筑或纹理。大图前景 buffer 和填补会增加 CPU/内存，尚无大图实时性能证明。纵向身高、腿长与体态重塑需要后续专用算法。修改上游几何/顺序后应重新检测，尚无自动坐标重投影。

## 2026-10-13 算法整改

非零命名身形参数必须有subjectMask、bodyPart和所需关键点；错部位参数明确报错。骨轴、法线、半径均使用像素空间；手臂贴躯干时使用近的自由侧轮廓跨度，避免取到躯干厚度导致0效果。收缩不重绘原alpha<.5外侧fringe，背景纹理不位移；窄带diffusion只负责局部底图延续，不与公开exemplar去人混用。裙下/交叠肢体和部分遮挡小腿不开放误导的独立重塑参数。

人体模型输出是类别confidence，尚非精确matting与部位像素解析；宽松衣服和遮挡仍有失败。重分割测量有噪声，不能以宽度delta或changedPixels单独验收自然度。所有原图/编辑/差分与失败保存在test/results/body-algorithms。
