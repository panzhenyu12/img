# FUNC-030 人像材质 ownership 候选

状态：ownership 分类器仍为隔离研究候选；本文后附的源颈缘误冻结修复已进入默认 Rust 核心，Web 尚未重建。

## 背景

当前下颌收窄路径把 `known_layer == 0` 同时当作“场景背景”和“没有可靠语义证据”。在脸、颈、头发的抗锯齿过渡中，这两个含义不等价：未知像素被当作场景 donor 时，会把旧脸缘或头发颜色扩散进新显露区域，形成断缝、黑边和脏色。检测器的轮廓也只是观测证据，不能直接当作解剖学脸颈边界。

## 候选策略

`core/image-core/src/face_ownership.rs` 定义了一个互斥的像素材质分类器。输入是独立语义 raster 的覆盖率，输出为 `Scene`、`MovingFace`、`NeckUnderlay`、`Hair`、`Accessory` 或 `Unknown`。

分类优先级遵循可见遮挡关系：用户保护/饰物优先，其次是头发，再是有明确前景优势的脸，最后是颈部 underlay。多个弱证据相互冲突时返回 `Unknown`，不把它降级为场景。只有 `Scene` 可以作为新显露场景的 donor；`NeckUnderlay` 和 `Scene` 才能作为收窄下颌时的底层 donor。

该模块目前是隔离候选，生产 `face.rs` 仍使用现有路径。原因是 ownership 规则必须在真实照片 holdout 上验证，不能用合成单测或几何门禁替代美学验收。接入前需要：

1. 将分类结果与当前 `known_layer` 逐像素对照，统计未知区域和 donor 变化；
2. 在至少三张不同肤色、发型和背景的照片上复核下颌正负方向；
3. 确认保护像素不变、场景直线不被错误填补、脸颈接缝没有新增颜色环；
4. 只有在真实照片整体优于当前基线时，才把候选接入默认 compositor。

## 回归

模块内包含 5 个单元测试，覆盖：

- 无语义证据才允许成为 clean scene；
- 头发与颈部重叠时头发拥有可见边界；
- 脸与颈同时高置信时必须有明确前景 margin；
- 用户保护和饰物具有最高优先级；
- NaN/Inf 输入只能得到 `Unknown`。

执行：

```bash
cd core/image-core
cargo test face_ownership
```

该测试只验证 ownership 契约，不代表人像算法达到 8 分，也不代表已经批准生产接入。

## 2026-10-26：源颈缘误冻结修复

新增 `core/image-core/src/face_source_fringe.rs`；连通边缘修复现进入默认 Rust 核心，ownership 分类器本身仍隔离。它处理的是“解析漏标被推断成其他人物”的源像素，而不是重新启用被否决的 destination gate。目的为 FACE-021 颈部/下颌连接与 FACE-023 保护边界；没有新增 Web、后端、MCP 或正式 `face.adjust` 参数。

用户图左颈 `(306,413..415)` 既有弱非零 skin alpha，又被推断冻结。新模块只对这一类未被显式保护的源像素重新做连通、前背景 donor 与 RGB 证据验证；通过后更新源物理 alpha 和推断冻结标记。原 donor 排除保留。背景、附件和用户保护不能因颜色相近而直接成为可移动皮肤。

`make quality-face-source-fringe`：覆盖 6 项辅助函数测试及 3 项公共入口回归，包含非零漏标、连续光照、显式冻结、远处同色人物、零候选及不相容颜色。三张缓存图的 ±60 回放显示用户图正向肤色突片消失、反向黑凹减轻；目标强度没有缩小。其他曲线问题仍存在，不据此打 8 分；已改默认 Rust 源码，未重新编译或部署 Web/WASM 服务。详情及证据路径见[复核记录](../qa/face-segmented-profile-20261026.md)。

公共入口夹具有独立 head matte 与连通颈部，对 ±60 用同一物理图像的完整语义参考验证材料运输；同时核验用户保护、耳/饰/发、低颈和不支持路径。旧分支红测在相同渲染函数中复现“弱解析边缘保持冻结”，当前公共入口通过。只重审 inferred && !owned 的边缘，不改已确认材质的 alpha。
