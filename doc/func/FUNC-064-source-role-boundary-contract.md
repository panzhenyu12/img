# FUNC-064 源材质边界判定与弱耳孤岛

日期：2026-11-16。独立 native/Python 算法修复，不涉及系统接入。

## 弱耳证据不能独自冻结脸颊

glasses-street 的耳后验在脸颊形成一个 13 像素内部孤岛，最高覆盖仅 .123，没有任何 >=.5 耳核心。旧耳连通策略却把所有未连接到耳核心且 >1/255 的像素冻结；该孤岛占据的网格进一步锁死四个脸颊控制点。

`face_ear_support.rs` 先在原始完整软耳支持上判断是否存在耳核心，再按照原有保护屏障判断与可动层的连接。只有完整位于裁剪内部、且不包含任何核心的弱证据岛，不追加耳专用冻结；皮肤、外发、附件、其他材质和显式用户保护的原判断继续有效。触及裁剪边界的组件可能在裁剪外含核心，继续保守冻结。真实耳组件的混合软边与受保护核心不能借此解锁。

原始耳概率和之前的耳 prior/donor 计算未改；源层仍须由修复后的真实 native 重新生成，不能沿用旧 alpha/B。

验证：

- 最终二维弱岛用例在旧逻辑失败，新模块 8 项通过，包含裁剪截断、保护屏障、软边与二维连接反例。
- 实际 native 的 14 项遮挡/耳部回归通过。
- 四图 native 对照仅 glasses 解除该 13 像素的错误冻结；woman/user/dark 的源层、位移场与最终 PNG 均保持精确相同。
- glasses 前 128 个控制与请求不变；原四个零位移位置恢复约 2.25px 动作。0/±30 真实回放保持零档恒等与固定区域不变。
- 独立查看原尺寸及放大图，脸颊曲线更连续，镜框、镜腿、耳钉和发丝未见新增断接，背景稳定。该局部修复通过；透明镜片内部编辑及大幅重塑尚未验收。

证据：`test/results/face-usable-20261112/motion-interface-20261116/ear-support-replay/`，测试反例另在 `glasses-street-runtime/ear-support-contract/`。

## 实验适配器必须服从原生采样语义

user 源像素 `(499,335)` 的同一附件边界，Rust f32 覆盖为 `.5000008940696716`，旧 Python/scipy 双精度结果为 `.49999999999999833`。因此 native 将它标为附件固定，Python 共动准备却不接收，产生四个冲突网格节点。

`geometry.py::_raster_mask` 按 `PreparedMask` 的实际 f32 运算顺序解码、归一化坐标和双线性采样，修正了这一不一致。未扩大阈值或加入 epsilon。栅格 invert 按原生处理；非空 strokes 明确拒绝，原 polygon 分支不在此次修改范围内。

七项采样测试对 20 组半覆盖、非整比、单像素轴、随机和反转输入调用提取当前 Rust 实现的 oracle，结果位模式及六种阈值判断精确一致；加关联附件与缓存测试共 17 项通过。真实 user 四个伪冲突消失，dark 原有零冲突保持。证据位于 `raster-sampling-contract/`。

## 共动与背景的独立结论

修复采样后，当前 parser 来源的 user 两只耳坠可在同一连续场中整体平移约 ±4.5px，材料与接触点刚性误差不超过 `1.4e-13`。但最初 source B 保留旧耳坠黑轮廓，故成片被明确否决。

随后固定完整位移场，按已有 context5 源背景和条件 alpha 下界重新生成本次源缓存，0/±30 的旧黑残影消失，独立视觉复核未见新增硬缝或大色块。此次使用原图自动组件提示生成、此前已选定的场景先验；只算该旧照片上新角色/场的兼容验证，不能算新泛化成功。没有搬用旧缓存或修改哈希冒充新准备。

下一步以另一张照片从源输入按同一规则准备背景与独立联合 alpha。class 6 眼镜与 class 9 耳饰虽在现有 accessory 字段合并，二者运动角色不同；不得把眼镜整体套入悬挂耳饰规则，也不得把类别概率直接宣称为物理 alpha。
