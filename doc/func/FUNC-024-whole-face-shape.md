# FUNC-024 整体脸型与可编辑预设

状态：开发中；整体宽度隔离原型，尚未接入网页/Go/MCP正式能力。关联需求：FACE-004、FACE-005、FACE-007、FACE-011、FACE-012、FACE-013、FACE-028、FACE-029。

## 用户行为

局部修型继续提供颧骨、下颌、下巴等控制；新增整体收放及脸型选择。先选风格、拖总程度，再做局部微调；允许关闭或替换风格并撤销。整体收窄、整体尺寸、短脸、组合预设分别呈现，不能混用同一个“瘦脸”名称。

当前原型只验证整体宽度。四种实验曲线为自然、椭圆、柔和、棱角；未实现脸长/五官联动，界面不能把它们显示成已经完成的完整脸型预设。竞品公开行为和证据见[调研](../research/pixelcake-face-shape-20261015.md)。

## 前端实现

待算法验收后，脸型面板分为整体模式与局部调整。预设保存稳定ID、版本、程度和局部增量，切换从同一原图计算；总程度归零恢复该预设之前状态。保持原有检测/手工轮廓入口，保存工程不依赖在线AI。未通过的能力不在生产滑杆中冒充可用。

## 后端实现与 Operation

仍使用共享Rust `face.adjust`。隔离原型拟定 `params.faceShape = { "preset": "natural", "amount": 30 }`，`amount`为[-100,100]，正值收窄、负值放宽；缺省对象表示不开启。`preset`仅接受 `natural / oval / soft / angular`，非法值显式拒绝。该字段尚未加入公共catalog，不应发送给现行Go/MCP服务。

原 `adjustments`保持独立。原型先合成一个目标轮廓，再交给既有变形器；不以一串已采样图片模拟预设。未来完整预设的五官目标应在同一检测坐标下联合求解，不能靠把几个旧滑杆顺序渲染就宣告完成。

正式接入时同时更新Rust验证、TypeScript类型、schema/catalog和Go/MCP发现信息；浏览器WASM和服务端native回放相同图操作。AI调用仍是可撤销提案，不能隐藏实际数值或覆盖手工调整。

## 算法与当前进度

原型位于 `experiments/whole-face-shape-v1-20261015/`，保持生产隔离。沿原脸坐标的纵向位置，用有界平滑宽度比例曲线协调额颞、颧、颊、颌、颏的目标；保留倾角和原始左右差异。目标映射可逆的证明只适用于该映射本身，不能推出后续位移场、遮挡合成或审美已合格。

完整产品预设还依赖整体大小、下脸长度、五官布局和背景材料修复。目前生产仍为v19 + physical-fringe-v2，原型不会自动修好已有耳根/旧轮廓/露底问题。

### 原图验证与已发现的问题

- V1 的目标曲线/协议测试通过，但三张原照的上、中脸实际位移接近零。用户原照 +30 请求上脸约 5.2/5.0px、中脸约 4.85/4.83px，最终上脸约 0.001/0px、中脸 0/0px；只下脸移动约 2.72/2.82px。因此 V1 不算完成整体瘦脸。
- V2 在 `experiments/whole-face-shape-v2-20261015/` 验证头部与相连颈部共用覆盖及速度场，解除本人的脸—耳—发内部固定边界。第一版因果实验的用户原照 +30 上脸实际约 5.19/4.99px、中脸约 4.83/4.80px，负档方向相反，确认旧内部约束是整体收放无效的直接原因。
- 第一版 V2 在整个局部计算框释放头部材料，存在误改其他人物的风险，已保留为失败候选；后续按选中人物的头部组件限定归属，并通过同一计算框内另一人物的公开操作回归。**几何可动域与物理 alpha 分开，不因 alpha 小就把本人边缘固定，也不因在计算框内就当作本人。**
- 原尺寸核对 V2 用户照 ±30：耳朵外边仍有浅色包边、暗线或橙色双轮廓。真实位移改善尚不能推出自然度合格；颜色分解、旧位置清除和遮挡合成仍待修复，未替换网页版本。
- 独立审查进一步发现：两头分离时另一头保持不变，但仅增加一条 4px 高的头发连接，就会把另一头的 1056px 全认作同一组件。最终一致输入从head重建0.5等值轮廓并使桥内头发/皮肤互斥，+100/−100分别误改645/650px，最大单通道差152/156；早期原测试轮廓对照为644/649px，单独保留。显式保护有效；仅靠连通组件仍不能确定人物身份。当前解析的 head/faceOutline 是语义类别并集，不能充当独立实例证据。接入前需要可靠实例归属或明确保护输入，歧义要报告，不能静默修改。见[独立审查](../qa/whole-face-v2-instance-owner-review-20261015.md)。
- 饰品也未合格：同一用户照 ±30 的耳环横向尺度分别约 1.08/0.92，连续位移并不保证金属饰品形状合理。后续需把耳部的非刚性连接与饰品的形状保持分别建模，不能恢复整个耳区固定来掩盖问题。

## 完成标准与测试用例

- 原型：0、±30、±100方向正确；上中下轮廓协调移动，保留倾角/不对称；闭合目标不自交；非法输入拒绝；旧参数回放不变。
- 实图：固定三开发原图与检测，至少比较0、±30及强档；原尺寸查看五官、头发、耳垂/耳饰、下颌/颈部与背景。记录目标和实际位移，不能用减少变形规避失败。
- 完整预设：切换幂等、程度归零、局部增量不丢失、撤销/重做、多人target隔离、手工保护不变。
- 发布：native/WASM/Go输出一致，页面导出与预览一致；整体观感和各关键接缝都通过后才算已验证。
