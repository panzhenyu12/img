# FUNC-008 第一期 Web 手工修图编辑器

状态：已验证（第一期手工Demo；15项浏览器验收通过，真实模型推荐除外）。

最后更新：2026-10-12

## 关联需求与范围

本功能实现 `doc/feature-list.md` 的手工编辑入口：CORE 非破坏编辑、历史、画布与导出；WARP 几何变换、网格和液化；FACE/FEATURE 脸型与五官参数；SKIN 皮肤及局部修复；BODY 身形；CLOTH 衣物；COLOR 调色、曲线和 HSL；FILM 胶片模拟；REPAIR 仿制、修复和传统内容感知填补。用户不需要 AI 服务、模型密钥或登录就能操作手工功能。

全部参数名称和取值范围以 `apps/web/src/core/registry.ts` 为可执行对账来源。UI 不生成未经注册的调整 key，Rust 引擎再次校验参数。AI 通过相同 Operation、区域、蒙版和笔画调用这些功能。

## 渲染和原图保护

导入时浏览器解码一次并保留不可变的原始 RGBA。每次编辑把原图副本和当前 EditGraph 提交给 Web Worker，Rust WASM 按历史顺序返回新图像。Canvas 只展示结果，不包含瘦脸、调色、液化或滤镜的 JavaScript 算法。原图与输出缓冲区独立。

WASM 边界：

```text
render_rgba(width, height, Uint8Array pixels, JSON.stringify(editGraph))
  -> { width, height, pixels: Uint8Array }
```

拖动参数使用短暂合并与渲染调度；单个 Worker 只执行一个请求，新预览替换旧预览，AbortController 终止正在执行的旧预览 Worker，过期结果不覆盖新预览。导出和工程校验使用不可变参数快照并排入独立队列，不被滑杆变动取消；滤镜缩略图使用后台任务。图片上传期间允许继续手工编辑，上传完成仅替换 `sourceAssetId`，同时更新历史中的 asset ID，不丢弃已编辑 Operation。图片超过 3200 万像素时在创建大型 Canvas 前返回明确提示。

## 用户行为

1. 导入 JPG/PNG/WebP；Go API 可用时创建临时 session 并上传原图。
2. 选择工具。人物调整先在画布上标记区域，或主动点击本地检测按钮；矩形、椭圆、套索、多边形均可使用。
3. 滑杆、数值输入、画笔或拖动控制点改变参数，形成新的 Operation 或更新当前 Operation。注册参数滑杆、标签与数值输入可双击恢复默认值。
4. 操作图层可独立开关、删除、重置和上下移动；Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y 重做。
5. 点击原图对比或按住空格查看原图；分屏对比提供位置滑杆。画布支持适应、原始像素 100%、缩放和平移。
6. 保存操作工程 JSON、复制参数或载入/粘贴操作工程。工程文件保存参数，恢复时先导入原图；不需要数据库。导入先规范化版本、ID、enabled、params 和 controlPoints，随后用 Rust 实际重放全部候选操作；验证成功才写入可撤销历史，无效工程保留已有编辑。校验期间已有新的手工编辑或更换图片时不覆盖当前状态。
7. 导出 PNG 或 JPEG；JPEG 可选质量并将透明区域铺白底。导出始终使用已应用的图，不包含待确认 AI 提案。

## 参数协议

```json
{
  "type": "face.adjust",
  "params": {
    "region": {"x":0.2,"y":0.1,"width":0.6,"height":0.7},
    "adjustments": {"faceWidth":-15,"jaw":-8},
    "opacity":100,
    "blendMode":"normal"
  }
}
```

坐标和区域使用 `0..1` 归一化。笔刷 radius 按图像短边归一化，strength/opacity/羽化为 `0..100`；图形裁剪使用像素，旋转使用度。Inline mask：

```json
{
  "shape":"brush",
  "strokes":[{"x":0.5,"y":0.5,"radius":0.04,"strength":80,"erase":false}],
  "invert":false,
  "feather":15
}
```

线性蒙版使用 `from/to` 归一化坐标；径向蒙版使用 `region`；多边形使用 `points`。冻结保护使用相同协议写到 `protectMask`。

液化 `mode` 包括 `push`、`pinch`、`bloat`、`twirl` 和 `reconstruct`。旋转笔画带 `direction: 1|-1`，重建恢复本液化操作层的输入像素并继续遵守蒙版/冻结；不撤销其他操作。对称液化生成明确的镜像笔画（`x -> 1-x`、`toX -> 1-toX`，旋转方向取反），AI/native 重放无需另行理解 UI 对称开关。

取样选区修补复用 `repair.clone`。UI 将目标选区按短边归一化笔刷半径的小于半径间距生成仿制笔画，用源中心与目标中心偏移计算每个笔画的 `sourceX/sourceY`，并用选区形状蒙版约束覆盖。超出源边界的坐标截断到 `0..1`，源边缘可能重复；超过 4096 个笔画时提示缩小选区或增大笔刷。

## 可选 AI 与检测

MediaPipe 只在用户主动点击时加载本地模型。检测失败保留手工区域编辑。多人检测结果可切换，区域可创建独立调整层。

AI 请求前先获取服务端 revision 并同步当前手工图；提案作为临时预览追加到渲染请求，不进入历史、工程或导出。接受前检查当前本地图仍与服务端提案基础图一致，避免覆盖用户继续进行的手工编辑；拒绝使用独立 `/reject` 接口。缺少模型密钥或服务不可达会显示提示，手工功能继续工作。

## Demo 的实际约束

- 当前像素执行是 Rust WASM 的 CPU 算法和 Canvas 展示。尚未使用 wgpu/WebGPU、瓦片缓存或 GPU shader；Worker 保持界面线程可操作，但大图和长操作图仍需要计算时间。
- 脸型、五官、身形和衣物形变按照用户标记区域内的相对位置执行局部形变。MediaPipe 提供可选检测区域和点数据，目前不把精确关键点作为每个形变参数的锚点；侧脸、遮挡、倾斜与不标准构图需要手工修正区域或使用液化/网格。
- 磨皮、褶皱平整、眉色、唇色和发色等依据区域与蒙版进行像素调整；尚未自动分割皮肤、头发、牙齿或衣物。手工绘色和修复可配合蒙版细调，多人独立效果用多个区域操作层。
- 内容感知填补使用传统邻近纹理填补。大人物移除、复杂结构和重复纹理需要结合仿制/修复；不包含生成式场景重建或成熟的全局 PatchMatch 实现。
- 胶片预设是十四种可调风格模拟和 `.cube` LUT，不宣称精确复刻富士相机配方。缩略图确实由当前原图缩小后执行 Rust 滤镜生成，最长边 120 像素；预设调整和叠加作用于编辑图。
- 选区、蒙版、笔画和网格坐标相对于操作执行时的画布归一化。裁剪、旋转或尺寸变化会影响其后的定位；重排几何操作后可能需要重新标记区域。
- 操作工程保存参数，不内嵌原图。导入应用于当前载入的原图，文件名与 asset ID 不会替换当前图片；不会自动从云端找回原图。PNG/JPEG 导出保留像素效果，不保留相机 EXIF、RAW 或专业色彩配置。
- 当前最多 3200 万像素、256 个操作；Rust 对单操作笔画和控制点另有上限。无账号、收费、数据库、云端持久存储和批量工作流；AI 与自动检测都是可选入口。
