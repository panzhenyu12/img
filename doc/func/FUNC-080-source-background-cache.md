# FUNC-080 同源瘦脸背景重建复用

## 问题与范围

普通 `adjust_face_with_source_layers` 每次滑杆请求都会重新计算同一张原图的背景层。2026-11-19 对已验收的 1024×874 胡茬照片实测：单次约 5.36 秒，其中背景重建与源颜色配对约 2.90 秒；随后顺序三次总耗时中位数约 5.40 秒。计时不包括前置模型、输入解码与 PNG 保存，不能换算为浏览器帧率。

这次只优化重复计算，保持当前形变与合成结果。原普通接口仍可无缓存使用；不接入 Web、Go 或 MCP。

## 接口与失效合同

调用者持有 `FaceSourceCache`，通过 `adjust_face_with_source_cache(source, params, layers, &mut cache)` 编辑。缓存按需创建，首次非零请求仍执行完整重建；不能将首次耗时从性能报告中隐去。`clear()` 可显式释放缓存。

缓存只覆盖 `reconstruct_source_background` 与随后的 `layer_pair::pair`。完整输入必须精确相等：源裁剪 RGBA、孔洞支持、覆盖率、供体保护与排除、已知材料类别、初始背景估计、场景颜色证据及其解释方式。输入变化时重新计算。不使用文件名、图片尺寸或滑杆数值代替输入绑定。

缓存返回独立输出副本，随后应用场景先验不能污染缓存中的原始配对。每次请求照常验证源图绑定、非法覆盖率与几何证据，并重算请求相关的运动域扩展、控制点、速度场和最终采样。尤其运动域的扩展距离依赖本次目标位移，不属于源缓存。

## 验证记录

实现已通过两项内部缓存测试和两项普通 Rust 入口测试，覆盖完整键变化、输出副本隔离、清空、零值、双向调整、保护更新、非法源绑定/覆盖率/private 参数拒绝，以及缓存命中后仍应用改变了的场景先验。

基线来源是 `test/results/face-performance-20261119/`。冻结实拍依次执行 `0/+30/-30/+60/-60/+30/+30/+30`，用 `experiments/face-performance-20261119/check_replay.py` 与此前已审查成片比较，8 次解码 RGBA 全部相同。零值不建缓存，首次非零 1 次未命中，随后 6 次命中。这项相等性检查只证明优化保留原效果，不增加美观评分。

同机顺序三次的原接口 `+30` 为 5334/5496/5403ms；缓存热调用为 2488/2430/2402ms，中位数约 **5403→2430ms**，减少约 55%。首次缓存填充仍约 **5274ms**。正负 30/60 的热调用为约 2.35～2.57 秒，**仍不适合实时滑杆**。本机非独占环境；这些是 native 算法调用时间，不包括模型准备、解码和存图。后续运动场/采样与其余源计算仍需优化。

照片、模型、缓存数组、生成图片与原始计时日志仅留本地，不提交远端。
