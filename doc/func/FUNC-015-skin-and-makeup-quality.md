## 用户行为

在“皮肤与质感”或“五官与妆容”中自动检测人脸，再调数值。模型在浏览器本地提供关键点和像素类别蒙版；调色与形变由 Rust 执行。没有检测结果时，皮肤工具可用明确的手工选区，或在绘色图层中涂口红、腮红、高光、修容；五官界面按实际语义区域开放对应参数。检测功能与 AI Agent 相互独立。

同一人脸可从皮肤工具切到五官工具继续调整，检测区域跟随保存的操作工程回放。检测针对当前图层的输入图像：先渲染此前图层，不包含当前图层自身；新建图层时使用全部已有操作的输出。因此，先裁剪再检测时，坐标对应裁剪后的图像。手工重新框选会清除此前检测语义，避免把旧脸部位置误用于新选区。

修改检测图层之前的几何操作或重排图层后，需要重新检测；当前没有自动重投影旧关键点与蒙版。

2026-10-14 修复工具栏跨出/返回人像工具、工程导入与历史图层点击的检测上下文不一致。三条真实流程回归验证直接切换、导入恢复和前置几何改变后重检；新增同类层在已有形变之后先建立没有旧语义的零参数待定位层，再针对新输入检测，避免把原层自身之前的坐标复制到后续层。输入几何指纹在当前编辑会话内跟踪，不随工程持久化；导入按各层声明输入初始化，不能验证外部改过坐标但保留旧mask的工程。输入改变只关闭陈旧控件/上下文，不自动删除或禁用既存工程操作，重检前预览仍可能包含旧层作用。用户照片71项单项回放、37个实际UI滑杆与11项导出对账详见[用户五官审计](../qa/user-feature-audit-20261014/review.md)；眉峰/眉尾连带眼睑、唇亮度/饱和度极端失真及弱鼻梁响应保留为失败，不提高质量评分。

## 前端与后端实现

- `apps/web/src/core/landmarks.ts` 按 MediaPipe 标准 mesh 索引生成 face/skin、左右眼睛、左右眉毛、嘴唇、内嘴、左右眼下 polygon。嘴唇与眉毛使用有序轮廓；眼下区域按眼宽缩放，并跟随人脸在图像平面内的旋转角度。
- `apps/web/src/App.tsx` 将 `semanticMasks` 随 `skin.retouch`、`feature.adjust`、`face.adjust` 序列化；不会向绘色、修复、滤镜等操作注入此字段。
- `core/image-core/src/color.rs` 在相应语义区域执行颜色/肤质算法；`geometry.rs` 将眼、眉、嘴的形变模板定位到真实特征边界，选区及冻结权重参与位移场。
- Go API 使用同一个 native Rust 核心；MCP/AI 调用可使用相同参数。新增 schema/catalog 仅同步现有功能协议，本次不扩展 Agent 工作流。

## 算法

显式 `semanticMasks.skin` 是皮肤覆盖范围的权威来源，不与更大的 face 区域合并；没有 skin 蒙版时才退回 face 或手工框选的近似区域。皮肤编辑还会减去眼睛、眉毛、嘴唇、内嘴及显式 hair/skinProtection。

磨皮使用有蒙版的 Fast Guided Filter（He & Sun 2015）生成明暗基底。RGB 共用亮度引导，分析栅格最长边上限 512px；仅把有效皮肤、非冻结且非透明像素按权重汇总到分析栅格。半径随关键点脸宽调整，缺少关键点时随手工选区调整。在原始分辨率插值线性系数，使用中尺度亮度估算基底，避免把分析图直接放大成模糊皮肤，也避免原始像素噪声经线性系数反馈成锐化。

`SkinDetailPlanes` 用两次有蒙版的归一化高斯卷积区分单像素噪声、中尺度肤色起伏与连贯的毛孔细节。单像素噪声和中尺度起伏分别衰减，细节不再统一乘一个残差系数；强明暗边缘降低修正以避免暗边/亮晕。因此 smooth100/texture0 不会把正常连贯毛孔全部抹掉，也不是简单降低强滑杆的有效数值。

较暗或较红的局部异常单独按连通性、尺度、长宽比和紧凑程度筛选。低反差的单个小点、长线、大片阴影及靠近保护边界的候选被排除；保留的紧凑候选从非保护、非透明的周围干净皮肤估算颜色，并渐变融合。`texture` 控制正常纹理保留，不关闭这一修正；`smooth` 连续控制总体强度。它是确定性的经典图像启发式，不是训练的祛痘/祛斑或材质模型，无法可靠判断痣、雀斑和痘印，必要时应使用已有保护蒙版。

此改动处理了旧高斯残差门限把深色小斑点误当成轮廓而完全保留的问题。新增已知场景测试验证：小斑点变浅、细噪声减少、宽范围明暗梯度及强边缘保持、纹理保留的方向正确。非皮肤、五官、头发、眼镜/耳饰、耳部、skinProtection、protectMask 与透明 RGB 均不能污染皮肤平滑。解析器当前使用 BiSeNet 像素分类生成 skin/hair/accessories/ears/neck；分类置信度按编辑覆盖处理，不宣称真实发丝 matting。

为降低热运行开销，命名蒙版在一次皮肤 pass 内编译一次：polygon 提前剔除包围盒外像素、raster alpha 一次解码，不再每个皮肤像素重新解析 JSON 五官轮廓。PreparedMask 与原始光栅器逐点精确对照，包含凹轮廓、羽化、增删笔刷、反选和软 alpha；通用最终合成复用同样的准备步骤。
美白调整近似亮度，冷暖和红润调整色度。两类调整均降低深阴影和高光中的强度；色度调整尽量保留亮度，并在 RGB 色域边界压缩色度。当前计算仍基于 gamma 编码 RGB 的近似亮度，不是线性光或完整感知色彩空间处理。

2026-10-14 冷暖 v2 将黄蓝调整与红粉色素分开：冷端最大变化由当前绿蓝色差约束，避免低黄色皮肤跨入紫色；暖端使用有界黄轴响应与较小红轴联动。仍保留明暗、毛孔、高光及语义保护。九张独立原照八组参数共72项同参回放中，36个零值/未变功能控制与基线逐RGBA相同；新增两个修改前失败/性质回归。冷端改善明显，强暖仍偏金黄，整体暂评7.6，未达到8分；不是自动白平衡或肤色均匀化。详见[冷暖v2复核](../qa/skin-warmth-v2-review.md)，v1偏黄候选的报告与图片亦保留。

明确 `redness<0` 的去红 v6 以最长边192px的有界栅格取周围有效皮肤红绿色度35%分位，并扩大参考邻域避免宽红斑自我污染；另估计邻域绿蓝色度，减轻单独减红留下的紫灰色暗点。正常皮肤只作轻微全局响应，主要修正局部红异常；冻结、透明、未选、五官、头发和语义保护区域都排除为供体。零亮度色度重建保持原有毛孔、明暗与alpha。它只改善颜色，不修复囊肿凸起、凹陷或暗痘印结构；`redness>=0` 和未请求去红的既有输出不变。

唇色、唇明亮与饱和度使用外嘴唇区域并排除内嘴；唇色以原图亮度和局部色度为基准，高光/近中性色降低染色，牙齿 polygon 为硬保护，避免羽化边缘染色。眉毛深浅按有效皮肤低频估计与眉毛原始亮度差区分发丝和眉间皮肤；没有皮肤参考时保守回退。它们仍是确定性局部颜色场，不是学习到的口红/眉毛材质模型。三张独立人像两类妆容共30项回放，妆容自然度暂评7.2，详见 [妆容材质 v1](../qa/makeup-material-v1/review.md)。当前开放的黑眼圈 `darkCircle` 在存在眼下语义区域时使用邻域皮肤的低频光照平面和有限色度校正，减弱固定加亮造成的灰白块。v5 以三轮 Tukey 权重压低周围高光/腮红异常供体的影响，并按原图相对低频面的细暗残差保护遗漏的睫毛、眼镜线和下睑线。七个样片版本四档强度共28项回放；普通正脸自然档暂评约7.7，眼镜旧缓存仍有漏分，未达到全部8分，详见 [稳健眼下复核](../qa/under-eye-v5-review.md)。眼袋 `eyeBag` 和泪沟 `tearTrough` 没有已验证结构算法，前端隐藏、非零调用明确拒绝，不能当作已完成美颜功能。

五官几何的眼、眉、嘴中心与影响范围由实际 polygon 边界确定。同一五官图层同时调整妆容与几何时，先在输入图像上着色，再进行几何反向取样，让唇色等妆容跟随形状移动。

唇明亮 V2 在现有唇色/饱和度重建之后，把 RGB 解码为线性值并共用缩放系数。正向令 `g=2^(brightness×lipWeight)`，系数为 `g/(1+max(linearRGB)×(g−1))`，避免裁切和黑纹加白；负向采用 `2^(brightness×lipWeight×diffuse)`，其中 diffuse 沿用中性高光置信度。编码回 sRGB 前不分别裁切通道。亮度为零时不进入新变换，alpha=0 跳过亮度处理。此处 brightness 已归一化为 −1..1；正饱和通道无保色提亮余量，不能保证任意颜色仍有明显正向响应。这是确定性亮度修复，不是反射率真值恢复；唇色与饱和度算法未重做。

对称调整在可靠、完整的眼睛/眉毛/嘴唇语义区域上保守调整二维位置与嘴角高度，分别取样每一侧自己的纹理；没有可靠语义时前端隐藏该入口。当前不做三维姿态校正、侧脸透视恢复或整脸轮廓对称。脸型与五官结构的实现和未开放参数以 [FUNC-010](FUNC-010-parameter-ledger.md) 与 [FUNC-011](FUNC-011-face-contour-quality.md) 为准，不把手工模板或参数存在视为语义重塑完成。

## 参数结构

```json
{
  "type": "skin.retouch",
  "params": {
    "smooth": 30,
    "texture": 60,
    "whiten": 20,
    "warmth": 10,
    "redness": -10,
    "semanticMasks": {
      "skin": { "shape": "polygon", "points": [{"x":0.2,"y":0.2},{"x":0.8,"y":0.2},{"x":0.5,"y":0.9}], "feather": 2 },
      "lips": { "shape": "polygon", "points": [{"x":0.4,"y":0.7},{"x":0.6,"y":0.7},{"x":0.5,"y":0.78}] }
    }
  }
}
```

`semanticMasks` 使用命名的 inline mask 或 3–256 个点的紧凑 polygon 数组；Rust 严格校验名称与 mask 结构。坐标归一化，对应操作输入图像。`feature.adjust` 的数值放在 `params.adjustments`，共用同一语义蒙版。通用 `mask`、`protectMask`、opacity 与 blendMode 继续限制最终合成；`protectMask` 还排除磨皮取样来源。

## 完成标准与测试

- Rust 颜色回归验证显式 skin 不被 face 扩大、受保护区域改变颜色不会污染邻近皮肤磨皮，以及美白/冷暖/红润的深阴影与高光保护；同时覆盖牙齿独立美白、红唇/口腔保护、眼下排除眼球和色度边界。
- Rust 几何回归验证真实眼/眉/唇位置发生变化，旧固定位置保持；polygon 与保护权重进入位移场；同层唇色跟随嘴形；对称调整保留各侧纹理，无可靠语义时保持原图。
- Playwright 用真实人像检测、拉动肤色滑杆、保存语义参数，验证眼部与背景采样不变；切换五官及创建手工妆容图层无协议错误。
- 同一图像/工程在 WASM/native 的输出逐像素一致，是工程合同；不能从通路一致性推断美颜质量。
- 既有 `skin-guided` 48 项为六个样片版本 × 八种肤质/肤色参数，最长边 1024px，支持域外和 alpha 变化均为 0，native 总进程时间 229.43–662.15ms，未计模型初始化与解析。48 张 comparison 的左/右栏分别核对为原图/输出裁切，没有旧 Gaussian baseline；不作“优于旧版”的实拍结论。
- 紧凑白头v4c候选在固定三图九项中减弱白头31%–50%，但逐一复核13个新增变化连通域时发现油脂高光被误修及真实白头的暗环残边；函数、生产调用及候选单测已撤回。补丁见[白头候选](../qa/skin-bright-v4c-review.md)，最终逐域证据见[撤回报告](../qa/skin-bright-rejected/review.md)，不能把候选测试/对比当作生产实现。
- 全部八种参数已按六张九格证据目视，代表性的自然/强磨皮、美白采用原尺寸复核。smooth100/texture0 在深浅肤色、带妆、旋转图均有明显毛孔消失与蜡感；smooth60/texture60 更保守，但未证明选择性祛瑕。详见 [复核报告](../qa/skin-guided-review.md)。
- 48 项没有唇色、眉色、牙齿或眼下操作；独立 feature 缓存只证明有限样片的局部着色。闭嘴图牙齿美白零变化不能当有效美白通过。`portrait-roll` 为带妆图旋转派生，六个样片版本只有五张独立原照。
- 多尺度版本在同一缓存、同一参数上新增 48 项 `ea5b404`/当前 native 对照，不覆盖旧证据。新增已知场景回归在修改前失败：强档正常毛孔对比10→0；texture100仍保留瑕疵；第一轮低反差红斑15→13。最新版分别保留毛孔对比8/10，降低瑕疵对比39.75→10.15/11.72，红斑剩余色差15→9。已知模拟场景只能证明算法行为，不能替代实拍质量。
- 此前多尺度v3已检查六个版本的自然/强磨皮/texture100 原尺寸裁切；48项支持域外及alpha变化0，其中肤色30项与ea5b404基线逐字节相同，当时没有改善旧版冷调偏粉紫、美白层次问题。耗时区分native总进程与同进程graph+edit热运行；现场并发编译/Chrome负载且部分超过目标，不称实时或效率达标。
- 局部去红 v6 新增两项回归：红斑相对健康皮肤优先改善并保持毛孔/亮度；冻结和语义保护供体的红/青色不可污染邻域参考。九张独立照片×四档共36项中域外及alpha变化均为0，负档最大亮度偏差0.50/255；逐张温和/强档整体与100%裁切已复核。最终18项负档native总进程124–637ms，中位数259ms；含I/O且有并发负载，没有浏览器热帧验收。见[36项报告](../qa/skin-redness-v6-final.json)。
- 本次[默认输出对账](../qa/skin-redness-default-parity.json)使用独立不可变v3/v6 binary，并在每次spawn前后校验SHA：36项 `redness=0`（其中18项自然/强/纹理磨皮）及6项 `redness=+40` 均与v3 PNG逐字节相同；只有6项明确负值去红改变。该对账只证明默认输出未回归，不能证明旧美白、冷暖或红润达到8分。

## 当前限制

自动 skin 由人脸关键点定位后的 BiSeNet 像素分类推导，分类仍可能在胡须、浓妆、暗光和遮挡边界出错；不是专门的皮肤材质、瑕疵或毛孔解析模型。眼下目前只有阴影改善，眼袋/泪沟结构重建仍待实现；手工画笔妆容也不等于具有皮肤材质的自动妆容模型。

多尺度分离减轻强档过度平滑，但自然档的细瑕疵改善仍偏保守；异常筛选不能可靠区分正常痣/雀斑与痘印，也不能重建凹陷疤痕、深皱纹或皮肤材质。经典保边和邻域修正不代表商业精修质量。冷暖v2改善低黄色肤色的冷调粉紫问题，强档仍可能偏粉或偏金黄，缺少光源/反射分解和均匀化；美白在原高亮区域仍可能减弱局部层次，本轮美白算法未变。当前 skin 类别包含可见 neck，不是全身皮肤统一调节。

48 项使用缓存 raster skin/hair/neck，没有当前新增的独立 accessories/ears 命名蒙版，因此不能据此宣称新增耳饰/耳部保护已完成实拍验收。极暗光、胡须/眼镜、真实侧脸、多人与有牙样片的妆容质量仍需分别补证；自动腮红/眼影/修容材质模型尚未实现。多图效果、定位和效率按 [逐功能8分目标](../qa/quality-targets.md) 分别评审；不能从像素检查或单测通过推断8分。上游几何或图层顺序修改后仍需重新检测，没有自动蒙版重投影。
