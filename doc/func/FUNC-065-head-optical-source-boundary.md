# FUNC-065 完整头部光学层与耳缘硬背景误判

日期：2026-11-16。独立 native 算法实验，未接入 Web 或服务端。dark 耳外旧轮廓点链消除后，固定源背景对照进一步减轻了细亮边；同规则 woman 长发照片的限定回归通过。上述结论只适用于实际审查的 `0/±30`，不记为整体可用或 8 分。

## 光学对象与运动权限分离

头部光学前景包含选中人物的脸、耳、耳饰、头发及相连颈部；衣物和外景属于相对背景。固定头发仍保持零运动和输出冻结，但它遮挡的背景不能因此被当成已观测颜色，也不能以头发 RGB 充当背景供体。

`source_layers.rs` 的独立光学模式按完整 alpha 确定隐藏背景，不再用输出冻结排除它；保留实际输出冻结和可见背景的保护。源 alpha、背景和预乘残差必须配对。完整观测域先估计，再嵌入既有形变视图，不能按旧 trace 截断头部。

dark 的完整观测域为 `[100,126,619,818]`，旧形变视图为 `[73,99,645,733]`。新增下方观测区的 alpha=0 部分均由完整 parser 判为衣物，保留原图作为可见 B，并排除场景供体。该特例不代表其他照片的裁剪外区域也都属于衣物。

真实 native 最小回归验证：旧实现仅改变前景是否冻结就会改变源 B；新实现修复这一行为。6 项测试覆盖静止前景隐藏背景、非零采样的输出保护、前景不得充当背景供体、旧头发背景标签，以及默认路径与旧 binary 的逐字节一致性。测试在 `test_head_source_roles.py`；这些合同不等同于真实抠图质量。

## 硬背景误判导致旧耳缘留在原地

第一次完整 head 方案使用大视野 parser 的类别轮廓和固定 6px 未知带。虽然形变连续、源重构和输出数值均通过，`+30` 的双耳外侧仍有离散棕色点链，实图被拒绝。

右耳五个反例均不是冻结像素：原 trimap 将真实耳缘设为硬背景，official alpha 因此被钳为 0；B 与原 RGB 相同，逆采样的四角也全为 0。原耳缘就被永久留在原位置。例如 `(479,517)` 的模型 raw alpha 为 `.935`，却被硬背景提示钳为 0。raw 数值只是冲突诊断，不能单独作为真实透明度证明。

已有 context5 背景先验的固定范围对照改动了 584 个输出像素，却未改变这五个反例，证明继续补背景不能修复该硬背景误判。保留失败产物，不扩大补丁范围掩盖原因。

## 多尺度观测只撤销冲突硬背景

`prepare_source_head_matte.py::reconcile_observed_trimap` 使用同一源图已保存的完整头部与精细局部后验：

- 完整视野继续定义对象和光学裁剪，保留原硬前景。
- 任一实际观测尺度的 head `>=.5` 支持及既定 6px 边界带，可以将原硬背景降为未知。
- 不把未知加硬、不新增硬前景、不让局部裁剪外的零填充参与投票，也不使用编辑后坐标生成提示。
- 保持模型、半径、形变场和 B 求解算法不变；MEMatte 对冻结的新 trimap 执行一次推理，保留 raw 与官方钳制输出。

dark 有 2,405 个原硬背景像素改为未知，硬前景零变化；这五个耳缘位置不再被强制钳零。9 项相关准备合同通过，固定 `0/±30` 成片中左右耳外旧点链消失，耳饰连接保留。零值与原图精确相同、冻结区域不变、native/Python 采样一致、输出无越界。独立查看全图、耳部、发际和颈部后，接受这一具体缺陷的修复。

右耳外仍有窄亮边，尚不能称耳周质量完全通过。跨照片测试继续使用同一规则，不按 dark 的失败坐标修补 mask 或颜色。

## 长发照片的固定规则回归

woman 复用合法的同源双尺度 npz 缓存，没有重新推理 parser；保持相同 BG-only 规则和 6px 半径。完整光学域为 `[0,107,636,823]`。唯一一次 MEMatte 后，原有 `0/±30` 形变场、冻结掩码不变，长发、两侧脸发界面、半遮耳及花纹衣领未见新增裂缝或残影，接受这一照片和范围的回归。

零值逐字节等于原图，native/Python 输出一致。`-30` 有 4 个通道到 `255.000015`，是旧场已存在的 f32 尾差；不能将其报告为浮点输出严格零越界。woman 与 dark 都是历史开发照片，这不是独立新样本的泛化验收。

## dark 细亮边的完整源背景对照

采样分解表明，右耳亮边主要来自露出的目标背景估计偏亮；不是冻结、网格断裂或数值截断。固定新 trimap、完整裁剪和模型，按 `trimap>0` 做一次 LaMa 背景推理，不扩大蒙版、不合并身体，不拼接历史局部先验。原图可见上下文保持精确不变。

完整光学域先配对：只有既有非零 alpha 支持可使用新 B，含零运动头发；alpha=0 的衣物/外景仍是原 RGB。alpha 只提高到给定 B 下有界前景颜色所需的下界，不声称恢复真实透明度。然后再嵌入旧形变视图，复用原 `0/±30` 场。

双向实图复核接受当前暴露区域的改善：右耳亮脊减弱、点链未复发、耳饰连接保留；相对上一份 native B，发际与衣领审查区域逐像素不变。零值恒等、冻结不变和 native/Python 一致通过，输出严格无越界；条件源 F 有 917 个通道的 f32 尾差，最大 `255.00001377`，超过 `255.0001` 的通道为 0。

推理为 CPU 3 线程、原尺寸 519×692，单次模型计算约 6.07s，含加载总计约 9.80s；不应宣传为实时初始化。生成 B 的头顶仍含模糊发形纹理，当前冻结场没有将其暴露到成片；因此这不是已恢复的完整干净背景，也不支持任意发型或头部外轮廓改造。新增脚本为 `face-source-scene-prior-20261110/infer_head.py` 和 `derive_complete_head_scene.py`，完整域配对有 4 项针对性合同测试。

## 用户原图与大强度边界

用户原图也按同一规则重新准备，没有使用历史 ZIM 透明度或挑选过的 context5 先验。项链将颈胸皮肤分成类别上的断开块，未知块穿过初始人工裁剪边。准备器此时回退到同一后验实际完整观测的原图域，保留原 trimap 和输出权限；真实照片边缘可截断，人工裁剪边不得截断未知支持。12 项源准备合同包含该回退、原图边缘和未观测区域的反例。

user 的初次 native B 仍在耳坠旧位置留下黑弧，明确拒绝。随后按完全相同规则进行一次完整源 B 推理与条件配对，`0/±30` 双向实图中的旧黑弧消失，耳坠、脸颈和项链接触连续，已独立与旧 context5 同场成片比较。发际/项链审查区相对初次 native B 逐像素不变，没有观察到生成的隐藏项链纹理泄漏。源条件 F 有 1,100 个 f32 尾差通道，最大 `255.00001225`，输出零越界。生成 B 会把项链延续到隐藏颈部，因此仍不能宣称完整干净背景或任意大位移已通过。

另固定 dark 完整源层扩到 `±60`：原 `+30` 场和图像精确复现；强档点链/亮脊未复发、无新裂缝。但独立评审发现耳槽在放宽时压窄、收窄时外翻，**强档自然度未通过**。不能以数值响应约 `.819` 或光学修复通过代替耳形验收；保留常用档结论，不在该照片继续扫描权重。

## 首张未参与调试的新原照

冻结 Pexels 2379004 的彩色微侧脸原照后，按固定长边 1024 得到 678×1024 输入。自动检测、同版材质/运动界面、完整头部 MEMatte、native B 和原约束求解均一次按既定规则执行，没有手工改像素、换失败照片或追加 LaMa。

`0/±30` 的原尺寸和局部对照经独立审查通过：胡须轮廓动作连续，耳颈和衣领完整，背景砖缝未见随人脸变形。近耳有小幅宽度联动，较大强度未验证。零档全 RGBA 不变；有源前景或输运前景覆盖以外的背景、原固定区和裁剪外区域变化均为 0；native/Python 输出精确一致，三档无输出越界。

独立检测耗时约 3.95s，MEMatte 推理约 1.41s；非零档几何求解约 .48–.50s、重采样约 10ms，单档 CLI 含字段导出/IO 约 2.8s，不能称实时交互。这里只是第 1 张独立原照，不是全数据集或总体 8 分。

原照及来源记录位于本地 ignored 的 `test/images/holdout-20261116/`，源码只新增 `detect_source.mjs` 调用现有检测模块的隔离空白页面。没有打开编辑器、运行产品流程或构建应用。

## 代码与证据

### 固定规则的四图收束与新原照强档

同一既有耳部 W10、4 次局部/全局迭代在完整源层上复核，没有扫描权重。dark 强档耳槽形状改善，但响应由约 `.819` 降为 `.745–.754`，仍不授予强档普遍自然度通过。新原照的强档响应仅由 `.975` 降为 `.949–.952`，耳廓较贴近原形，说明收益并非全部来自降低脸宽变化。局部求解仍需数秒，不能记为实时滑块。

对 woman 与新原照也按同样完整 trimap 做一次 LaMa 源背景预测，不按照片名选择旧缓存或单独范围。woman 的 `0/±30` 未见脸发界面、颈领或发际回退。新原照复用完全相同的 W10 场，只更换配对源层后，`+30/+60` 近耳下缘至后颈的浅亮带明显减弱；独立复核 `±30/±60` 未见新裂口、双轮廓或背景砖缝移动，接受这张照片的源背景替换。不能再把它的新强档结果写成旧亮边失败，也不将单图改善外推为整体 8 分。

`resample_source_layers.py` 固定已有场和真实源缓存来源，仅换源层重采样；新原照五档零值恒等、冻结区不变、未被前景覆盖的背景不变及 native/Python 一致均通过，输出零越界。全部新图使用同一源背景规则后，还需独立原照验证；隐藏背景仍是估计，不是已恢复真值。

### 单一离线算法入口

新增 `face_pipeline.py`，将已选方法串成一个固定候选：原图自动检测 → 同源多尺度后验 → 独立运动界面 → 完整头部 MEMatte → 一次完整头部 LaMa 源 B → 配对源层 → 有界共享场及固定 W10 耳材料 → 双向成片。它不按图片选择不同算法、不读取编辑结果修改输入、不构建或部署应用。

入口接收原图、带哈希的本地 native 工具清单和输出目录。默认 `0/±30`，保留各阶段日志与实际图片；失败就报告失败，不能自动换图或更改策略。`prepare_motion_interface.py --native-helper` 验证旧 helper 的生成源码及 binary 哈希后复用它，避免每张图重复编译。新入口的实际运行状态以 `pipeline.json` 为准，脚本存在不等于新图已通过。

### 2026-11-17：源附件计划前置与跨条件回归

Lupita 新原照暴露两类源准备错误。光学裁剪只覆盖到部分已经观测的颈胸未知连通域，准备器现在只在已有完整观测内闭合穿过人工裁剪边的未知块，未知数据仍拒绝。随后耳钉允许共动，但上游把耳钉当固定障碍留下的耳垂锁没有同步解除，造成六个几何固定点冲突。旧失败结果均保留。

`attachment_source_plan.py` / `prepare_attachment_source_plan.py` 复用既有附件核心及其连通软支持，生成同源运动计划，在 native 连通判断之前生效。整件附件遇到 user/hair/feature/garment 真实保护即拒绝；不剪掉保护片段强行通过。计划可以连接耳钉类别造成的耳垂缺口，但绝不并入 `joint_alpha` 或替换光学透明度，附件也始终禁止作为背景供体。原始材质后验不变。

`face_profile_replay.rs` 的 `sourceMovingAttachmentSupport` 对接私有研究输入，Rust 重新检查形状和保护冲突，Python 下游验证相同附件组件。它依赖自动源计划的身份验证，不能作为任意外部二值解锁接口直接开放给 MCP 或产品。

同一份 MEMatte/LaMa 源缓存复用后，Lupita `0/±30` 独立照片复核通过，耳钉、耳垂、脸颈连续，零值/冻结区恒等，输出无越界；非零求解约 4.19/4.42 秒。旧用户大耳环另做不重新推理的权限回归，alpha/B 与旧已验收层逐字节相同，双向耳环未见新分离、旧黑边或孔内填色。

固定两张原图继续验证：portrait-hair 长发样片普通 `±30` 初步可用，放宽时下颌接点略僵，未升精修评分；profile-hoodie 在关键点阶段失败。固定分块与原始检测器对照已将侧脸失败定位到 landmark/presence，不能用检测框替代完整几何，也没有降低阈值强行准入。完整边界见 [2026-11-17验收范围](../qa/algorithm-progress-20261117.md)。

源准备、附件计划和完整域配对共 23 项 Python 合同通过；Rust 针对源附件连通、alpha 独立、供体排除、真实保护冲突及空计划恒等的定向回归通过。测试只验证所述机制，不能给剩余脸型/五官或强侧脸授予效果通过。
